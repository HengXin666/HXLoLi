# B3 自检

日期: 2026-11-02 00:35 CST. 对象: 同目录 `index.md` 和三张图 `b3-1-layout.png` / `b3-2-step.png` / `b3-3-n.png`. 数字一律取 `b3_data.json` (run2).

## 1. 每张图在正文里被哪句话引进来, 证明哪条事实

| 图 | 正文里的引用句 (原文) | 证明的事实 | 图里多出来、正文没写的 |
|---|---|---|---|
| b3-1 | "上图证明"读"落在哪几个字节上. 红格是 `ob_refcnt`: float 槽位的第 0 到 8 字节, 列表槽位的第 16 到 24 字节." | 遍历写的 8 字节和 gc 写的 16 字节各在槽位哪里; 槽位 32 B / 64 B | 其余字段 (ob_type / ob_fval / ob_size / ob_item / allocated) 的偏移与 8 B 空位, 按字节等比例 |
| b3-2 | "上图证明复制的单位是页, 不是对象. float 每 128 个只读 1 个, 子进程仍弄脏 31292 KB. 全读是 31432 KB, 只差 140 KB." | 复制以页为单位; 拐点 = 一页放的对象数 (float 128, 列表 64) | 9 个 k 值 × 2 种对象共 18 个点; 拐点前是平的, 拐点后每翻倍减半 |
| b3-3 | "上图证明脏页约等于 N 乘槽位. 2M 个 float 实测 62808 KB, N × 32 B 是 62500 KB." | 脏页 ≈ N × 槽位, 误差约 0.5% | 5 个 N 值 × 2 种对象共 10 个点都落在理论线上, 不只是端点 |

正文里每个 KB 数字都在 `b3_data.json` 里找得到 (31432 / 31292 / 15672 / 62808 / 125560), 62500 和 125000 是 N × 槽位的理论值.

## 2. 把三张图全去掉, 正文能不能独立成立

做法: 删掉 `index.md` 里三行 `![...]`, 其余一字不改, 再跑 `hx_voice.py lint --profile article`.

结果分两层:

- **结论能成立.** 每条引用句本身带着它证明的数字, 去图之后读者仍然知道"写的是 ob_refcnt""拐点在 k=128""脏页 ≈ N × 32 B". 0x00 还有 ctypes 代码块, 0x03 本来就靠表格.
- **证据立不住.** 去图后正文只剩每条曲线的一两个点: b3-2 的 18 个点剩 3 个, b3-3 的 10 个点剩 2 个. 读者没法自己看出"拐点前是平的""每个 N 都落在线上", 只能信我挑的那几个数. b3-1 的字节布局去掉以后, "第 16 到 24 字节"是一个要读者在脑子里自己摆的位置.
- **门禁也不放行.** 去图版 lint 报 `E [section-visual] 2 处 @ 行 28, 33` (0x01 和 0x02 没有视觉), exit 非零. 原版 0 E.

所以图在这里不是装饰: 正文给结论, 图给结论背后的整组数据. 撤图丢的是可核对性, 不是一句话.

对照 A2 那三张生图: 同样只删它们 (留下 cow-bars 数据图), A2 正文一个数字都不少, 读者也不缺任何事实. 但 lint 同样报 `E [section-visual] 2 处 @ 行 15, 36` (0x00 和 0x02 只靠生图凑够视觉). 也就是说门禁对 B3 和 A2 的反应一模一样: 它分不出"撤掉丢证据"和"撤掉什么都不缺", 只数 `![`.

## 3. 这个主题里到底有没有值得画成图的东西

有, 但只有三样, 判据是"它的事实本身是一个形状, 用一句话说就会丢东西":

| 值得画 | 为什么是形状 |
|---|---|
| 对象按字节的布局 (b3-1) | 事实是"哪几个字节在哪个位置", 天然是空间关系; 用文字列偏移读者要自己拼 |
| 隔 k 个读一个的曲线 (b3-2) | 事实是"先平后减半, 拐点在一页对象数", 这是曲线的形状, 两三个数说不出"平" |
| 脏页对 N 的线性关系 (b3-3) | 事实是"所有点都在 N × 槽位这条线上", 线性只能靠多个点一起看 |

不值得画的:

| 不值得画 | 为什么 |
|---|---|
| fork 与写时复制的概念 (A2 的 cow-hero, A1 的 drawio) | 一句话说得完: "谁先写某一页, 内核才给谁复制一份". 画出来是机器人和书架, 或者三个方框两条箭头, 不多一个事实 |
| 引用计数被改一笔 (A2 的 refcount-touch) | b3-1 的红格已经把"写哪 8 字节"画准了; 手和计数器只是同一句话的插画 |
| gc.freeze 挡 gc 不挡遍历 (A2 的 gc-freeze) | 只有 3 个数 (62.0 / 0.1 / 61.3 MB), 一张 2 行表比图更好核对 |
| 一页里哪些对象被读 (原计划的逐页热力图) | 值得画, 但这次画不出: 沙箱内核里 `/proc/self/pagemap` 的独占位在写之前就是 1, soft-dirty 位清零后一直是 0, 读不到逐页状态. b3-2 用间隔扫描间接证明了同一件事 |

一句话: 这个主题里值得画的是**实测数据和内存布局**, 不是机制概念. 机制概念一句话能说清, 画出来只能是氛围.

## 4. 对 hx-note 的含义 (只记录, 本轮不改 skill)

- A2 的 patch 把"生图当主视觉"写成了硬规则, 这一轮证明它方向不对: 生图后端可用不等于该用. 规则应改成"每张图必须承载正文里引用的事实, 去图自检要丢信息".
- 原版 media.md 的问题也不只是"优先 drawio", 而是它按"画什么类型"选后端, 从不问"这张图证明什么". A1 的 drawio 和 A2 的生图是同一个错误的两种外观.
- `section-visual` 只数 `![`, 不判图有没有承载事实: A2 的三张氛围图同样让它通过. 能机械化的一步是要求每张图后第一句话里出现数字或代码标识符, 这条本轮没实现.
