0x02进门: 两级过滤

接进真实群聊和代码平台以后, 事件流是"高噪音, 低触发率"的: 大部分消息跟 Agent 无关.

所以先由程序挡一道, 再让模型挡一道.

每个来源可以设成三种之一: 仅响应明确请求, 作为候选事件, 直接忽略.

0x03已订阅的 Thread 直通

之后同一 Thread 的事件由程序直接送到那个 Worker, Router 不再调工具转发.

订阅是多对多的.

去掉直通以后, 完成时间基本不变, Router 的决定数多了约 30%, 总读缓存 token 从 2323 万涨到 3177 万 (约 37%).

实验是合成负载, 单次约 300 条消息里约 20 条工作请求, 每种方案重复 5 次.

0x04Router: 序点与批处理

双层架构取中间: 常驻的 Router 层承接所有入口的人类交互和全局协调, Worker 层并发干活.

Router 推理期间到达的 Trigger 先排队, 下一轮合并进一次 LLM 调用.

批处理摊薄的是 Prefill, 也就是输入侧的并行计算; 输出 token 的解码还是按长度串行.

0x08常驻不倒: 存算分离与 Watchdog

第一步把 Agent Loop 的计算放进云端无状态容器, Session 这些持久状态放进数据库.

三样东西拆开放以后, 云端的计算容器坏了可以直接换, 状态和用户机器上的环境都不跟着丢.

Watchdog 修一个卡死的 Loop, 做法就是扔掉当前计算容器, 从持久状态重建.
