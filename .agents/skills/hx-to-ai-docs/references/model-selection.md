# 模型选择建议

`makeDoc.py` 的 `--model` 会写进 frontmatter 的 `model` 字段, 记录**这篇笔记由哪个模型沉淀**. 它只影响元数据, 不影响生成质量.

## 规则

1. **能确定就显式传**: `--model "<当前实际模型名>"`.
2. **不能确定就写 `Unknown`**: 脚本在无法感知真实模型时默认就是 `Unknown`. **禁止**从 `config.toml` 或其他配置文件编造当前会话模型.
3. 环境变量优先级 (`makeDoc.py` 实际读取顺序): `HX_AI_DOCS_MODEL` > `CODEX_MODEL` > `OPENAI_MODEL` > `ANTHROPIC_MODEL` > `CLAUDE_MODEL` > `MODEL`; 推理强度取 `HX_AI_DOCS_MODEL_REASONING_EFFORT` 等; 两者会拼成 `<model>-<effort>`.
4. `.agents/skills/hx-docs-sediment/config.toml` 只是脚本的**可选 fallback 示例**, 不代表运行时配置, 默认全部注释掉.

## 该用哪个模型来沉淀

这是**人类的选择**: 不同环节对模型能力要求不同.

| 环节 | 要求 | 建议 |
|---|---|---|
| hx-docs-grill 反问 | 需要长上下文、能把握设计树 | 用你最强的推理模型; 这一步决定了后面所有工作 |
| 素材采集 | 需要工具调用与视觉 (截图识别) | 支持图像输入的模型 |
| 成文 | 需要中文文风与结构感 | 中上即可, 但标点/格式要严格 |
| 批量体检 | 需要一次看多篇 | 长上下文模型 |

**切换模型的代价**: 换了模型生成的笔记, `model` 字段要如实写新的那一个 —— 不要一篇笔记里混记多个模型名.

## 给人类的提示话术

当人类问"这篇该用什么模型写"时, 给一句可执行的建议 + 一句理由, 例如:

> 建议先用当前最强推理模型走完 hx-docs-grill (方向谈错的话后面全废), 成文阶段可以换更快的中档模型, `--model` 按实际使用的那个填.
