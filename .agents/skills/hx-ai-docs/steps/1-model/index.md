# 1 model: 找核心模型和翻车场景

只做一件事: 在动笔之前想清楚这篇要让读者带走什么. 产物是一份提纲, 放 `ai-docs/.hx-staging/<主题>/outline.md`

## 读什么

- 一手来源优先: 源码, 官方文档, 原视频. 固定到一个提交或版本, 记下链接
- 二手文章只当线索, 机制要回到源码核对
- 读的时候问: 这东西和同类比, 好在哪个具体的地方? 那个地方是怎么做到的?

## 提纲写什么

- **核心模型**: 一两句话. 读者记住它, 后面的机制都能推出来. 例如 "语言服务器回答的是内存副本, 不是磁盘; Agent 会绕过编辑器改文件, 也不会等"
- **机制列表**: 三到六个特色机制, 每个一行写清
  - 翻车场景: 不做这个会发生什么, 具体到命令或代码
  - 朴素做法: 一般人第一反应怎么做
  - 为什么坏: 朴素做法在哪一步出错
  - 怎么修: 它的实现, 附源码位置
  - 配什么: 一张结构图, 或 Compare / Flow / Fork 之一
- **用到我的项目**: 哪一条值得搬, 搬到哪个项目
- **不成立的条件**: 这些机制失效的具体情况

## 过关条件

- 核心模型能用两句话说出来, 而且每个机制都能挂到它下面
- 每个机制都有具体的翻车场景, 没有 "提升体验" 这类空话
- 功能清单, 版本比较, 安装步骤都没进提纲
- 拿不准的机制标了 [不确定], 没有编
