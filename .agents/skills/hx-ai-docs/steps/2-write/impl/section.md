# 一节的写法

以 oh-my-pi 笔记的 "写完当场拿到这次改动引入的错" 为例, 五步各一两段

## 场景

用读者见过的坑开头. "模型把 `user.name.toUpperCase()` 写进了 `name` 可能为空的地方" 比 "诊断可能不及时" 好记得多

## 朴素做法

写出第一反应, 而且要像是对的: "写完文件, 马上再调一次 diagnostics"

## 为什么坏

说清坏在哪一步: 诊断是异步推的, 刚写完拿到的是改之前那一份, 旧诊断是干净的, 模型以为没问题

## 怎么修

写它的实现, 附源码链接. 顺序或结构复杂就放图: 时序用泳道图, 并行用 Flow, 对照用 Compare

## 结果

一句话说修完之后读者能得到什么, 这一句适合用 `<Gold>` 或 `<Red>` 标出来

## 不要这样

- 把五步写成五个列表项, 每项半句话
- 只写 "怎么修", 读者不知道它在防什么
- 场景写成 "在某些情况下可能出现问题"
