# 2 write: 写正文

只做一件事: 按提纲写 `index.md`. 产物是 mdx 格式的笔记, 组件已全局注册, 不写 import

## 骨架

```text
frontmatter (加 mdx: 和缩进的 format: mdx)
# 标题
<Lead why claim use />
来源一句话, 带提交号链接
## 核心模型那一节 (标题就是模型本身)
## 机制一 ... 机制 N (标题是结论)
## 放到我的项目里
## 什么时候不成立 (用 <Boundary>)
## 留着查 (握手顺序, 源码入口, 可运行复现)
```

## 每一节怎么写

顺序固定: 场景 -> 朴素做法 -> 为什么坏 -> 怎么修 -> 结果. 做法见 `impl/section.md`

- 两到五段, 每段不超过 100 字
- 一个场景代码块, 或一张图, 或一个组件. 组件前后各一两句把它接住
- `<Red>` 或 `<Gold>` 每节最多一处, 不超过 30 字, 标读者最该带走的那句
- 标题写结论, 不写 `0xNN` 编号, 不写 "介绍", "概述"

## 过关条件

- 没有哪一节只有一句话
- 核心模型那节之后, 每节都能说出它在补模型里的哪个裂缝
- 示意例子写明是示意, 数字和机制都能在来源里找到
