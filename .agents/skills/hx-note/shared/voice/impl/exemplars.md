# 作者真文样本 (仿写用)

步骤 6 动笔前读一遍这份, 再写引入段. 黑名单 (`hx_voice.py lint`) 只告诉你什么不能写, 这份告诉你**照着什么写**

样本全部取自作者亲手写的 `blog/`, 一字不改. 读的时候只看三样: 句子多长、先说什么后说什么、情绪放在哪

## 样本一: 先交代处境, 再交代动作, 情绪在最后

出处 `blog/2025/06/21/01-八嘎日志-悬挂引用.md` 开头

```text
近日一名闲的没事干的小火子, 打算为远古的iocp对接协程并且支持超时; 以统一io_uring侧API;

故此需要伺候 MSVC、Win32 API

并且为了实现无单例架构和追求简易API原则.

使用了 建造者模式来封装 API...

一不小心 (说是不是故意的?) 就写了 悬挂引用了... 然后出现八嘎了
```

好在哪: 五行里没有一个概念解释, 只有"要做什么 / 为什么麻烦 / 怎么做的 / 出了什么事". 自嘲落在最后一行, 读者先知道事情, 再知道情绪

## 样本二: 一句话把来路说完, 然后直接贴现场

出处 `blog/2025/09/07/01-MSVC的requires缺陷.md`

```text
今天上win, 顺便把之前的msvc bug 修复. 结果发现: ([#13](...))
<紧接着是原样的编译报错>
经过排查, 发现是 msvc 的缺陷. 要求 requires 在函数签名中应该完全一样, 才会视作函数签名一样.
```

好在哪: 第一句就是时间加动作, 第二句是报错原文, 第三句才是结论. 结论之后马上给复现链接, 没有铺垫段

## 样本三: 一句评价代替一段解释

出处 `blog/2025/06/29/01-协程小细节.md`

```text
肥肠简单, 就是尝试读取 `STDIN_FILENO` (标准控制台输入流), 然后定时 `kt` 时间.

接口设计一目了然:
```

好在哪: 代码已经贴了, 文字只补一句"这段在干嘛"和一句态度, 接着又是代码. 文字是代码之间的连接, 不是主角

## 样本四: 动机写成一件真事

出处 `blog/2025/06/24/01-Linux常见Hook方法.md`

```text
这个是上班要求的, 不能使用 AI, 自己通过搜索, 把这个解决方案搞出来, 并且说明为什么选择这个方案, 不选择其他方案.

```

好在哪: "为什么写这篇"不是一句抽象动机, 是一个具体要求加一个具体结果

## 仿写怎么做

1. 读完四个样本, 先只写引入段 (50 字内) 给人看. 引入的事实来自 `intake.md`, 语气照样本
2. 判据: 把你的引入和样本一放在一起读, 分不出哪段是后写的才算过. 分得出来就重写, 不要去改单个词
3. 样本只学形状, 不抄内容: 作者的自嘲词 (八嘎 / 肥肠 / qwq) 是他自己的, 素材里没有对应的情绪就不要硬塞

## 怎么扩展

新样本 = 在本文件追加一节, 写清出处路径和"好在哪"一句话. 只收作者本人写的段落, 不收 AI 改过的
