> 这份文件是**本次沉淀的需求唯一事实源**。回答一个问题: 人类到底要什么, 以及**怎么算做到了**。
> 它必须活过上下文压缩 —— 所以它落在磁盘上, 且被后续步骤反向引用。

<人类原话 + 一句话复述。复述必须能被人类否决: 人类读完说"不是这个"就说明没对>

## 二、验收条款 (每条都可判定)

每条一个稳定 ID, 一旦定下就**不改编号** (改了就断掉所有引用)。

| ID | 条款 (可判定的说法) | 怎么算满足 | 状态 |
|---|---|---|---|
| G1 | <写成"做到时是什么样", 不写"要做好"> | <可执行的检查: 看什么/跑什么/数什么> | 待验 |
| G2 | | | 待验 |

**"怎么算满足"这一栏是硬要求。** 写不出检查动作的条款不算条款 —— 它是一条愿望。
愿望可以留在「背景」里, 但不能进这张表, 因为它无法验收。

状态的取值只有三个: `待验` / `已满足 (证据: ...)` / `已放弃 (原因: ...)`。
**不许留空**, 也不许写"基本满足"。
