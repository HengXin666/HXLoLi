# 保真盲审 prompt 模板

用在定稿前最后一关: 确认派生出来的人类文章**没有偏离**知识库那份原子知识点

派 sub-agent 时逐字使用, 只替换 `<...>`. **不要**告诉它哪份是"标准答案"以外的任何背景, 不要提示你担心哪里

---

```text
你在做一次一致性核对. 有两份文档:

A = <.hx-info.md 绝对路径>   (事实清单)
B = <index.md 绝对路径>      (面向读者的文章)

规则: A 是唯一事实源. B 只允许用不同的方式讲 A 里已有的东西, 不允许新增 A 里没有的技术论断

输出格式是硬性的, 会被脚本解析:
第 1 行只写 `verdict: PASS` 或 `verdict: FAIL`, 前面不许有标题, 空行或其他文字
之后依次写下面四个二级标题, 标题文字一字不改. 某节没有内容时, 正文只写一个 `无`

## 遗漏
A 里有, B 里完全没讲到的知识点. 每条一行, 以 `- ` 开头, 给 A 的行号与一句话说明
若 B 是有意只讲 A 的一部分, 也照样列出来, 由人决定是否接受

## 新增
B 里出现了, 但 A 里找不到依据的技术论断 (数字, API 名, 版本号, 因果关系, 性能结论)
每条一行, 以 `- ` 开头, 给 B 的行号与原文短引. 这一节里的每一条都是缺陷

例外: 引入段与展望段里的个人经历, 感受与计划来自作者画像, 属于文体要求, 不是技术论断, 不计入这一节

## 歪曲
A 和 B 都讲了同一件事, 但 B 把它讲反了, 讲过头了或讲窄了
每条一行, 以 `- ` 开头, 给 A 行号, B 行号与差在哪

## 理由
一句话说明判定. `## 新增` 与 `## 歪曲` 两节只要有一条, 第 1 行就必须是 `verdict: FAIL`

只做核对, 不要评价文笔, 不要改写, 不要建议扩写
输出 markdown
```

---

## 回收

存到 `<笔记目录>/review/fidelity-audit.md`, 原样保存, 不许改首行或删小节. 处理规则是**单向的**

- 「新增」里的每一条: 要么从 `index.md` 删掉, 要么先把它补进 `.hx-info.md` (补之前必须有来源依据). **禁止**默认保留
- 「歪曲」里的每一条: 改 `index.md`, 不改 `.hx-info.md`  除非核对后发现是 `.hx-info.md` 本身写错了
- 「遗漏」里的每一条: 由人类决定取舍, 结论写进 `.hx-mitemite.md`

判定 FAIL 时不许交付, 修完重跑一次 (换一个新 sub-agent, 不要在同一个上下文里复审), 用新报告整份覆盖旧报告

`hx_flow.py doctor` 会机械检查这份报告: 首行 `verdict: FAIL` 判红, 缺首行判红, `## 新增` 或 `## 歪曲` 去掉 `无` 与 `-` 之类占位后非空判红
