# 模板: 踩坑复盘

读者是**带着问题**来的, 而且很可能正在被同一个问题卡住. 任务: 读完能修好

## 槽位表

| 槽位 | 上限 | 必填 | 渲染成什么 |
|---|---|---|---|
| 现场 | 60 字 | ✅ | `# 标题` 下面的第一段, 不带小标题 |
| 症状 | — | ✅ | `## 0x00 <报错或异常现象>` |
| 定位 | — | ✅ | 多个 `## 0xNN <排查了什么>` |
| 修法 | — | ✅ | `## 0xNN <怎么改>` |
| 下次怎么避免 | 50 字 | ✅ | 接在修法段末尾 |
| 引用关系 | — | 自动 | 不写章节, 站点在页面底部自动渲染 |

## 现场

60 字以内. 写清楚**在做什么的时候撞上的**: 项目 + 动作 + 结果

作者的原句节奏

```
近日一名闲的没事干的小火子, 打算为远古的iocp对接协程并且支持超时
一不小心 (说是不是故意的?) 就写了 悬挂引用了... 然后出现八嘎了
```

禁止把现场写成"背景介绍". 禁止美化 (踩坑就是踩坑, 不要写成"一次有价值的探索")

## 症状

**必须给原始信息**: 真实报错文本、真实堆栈、真实的错误行为描述. 放代码块里, 不要转述.

脱敏只删敏感信息, 不许顺手"整理"报错  整理过的报错搜不到, 这一节就失去了唯一的价值

## 定位

按**实际排查顺序**写, 包括**走错的路**

- 走错的路要留: 它能让读者跳过同一个坑. 每条写清"为什么当时觉得是这里""为什么不是"
- 每一步要有依据: 看了什么代码、加了什么日志、跑了什么命令
- 禁止事后诸葛亮式重排 (把结论倒推成一条笔直的推理链). 真实的排查是绕弯的

## 修法

给**可直接抄的 diff 或最小片段**, 带分组名代码块

```cpp [修法-改前]
```

```cpp [修法-改后]
```

然后一句话说明为什么这样改能解决  对上「定位」里找到的根因

## 下次怎么避免

50 字以内, 接在修法段末尾, 不另起标题. 写**可执行的动作** (加一条 lint / 改一个默认值 / 换一种写法), 不写"要多加注意"

## 渲染后的骨架

```markdown
# <标题: 症状关键词 + 根因>

<现场: 60 字内>

## 0x00 <报错原文里最有辨识度的一句>

```text
<原始报错, 不转述>
```

## 0x01 <第一个怀疑方向>

<看了什么, 为什么排除>

## 0x02 <真正的根因>

<依据>

## 0x03 改法

```cpp [修法-改前]
```

```cpp [修法-改后]
```

<为什么这样能解决>

<下次怎么避免: 50 字内, 可执行动作>
```

## 这个模板拒绝什么

- **没有真实报错的主题**: 没有原始报错就不是复盘, 是讲解  用[interest-outlook.md](interest-outlook.md)
- **排查过程没记录的情况**: 事后补一条笔直的推理链等于编造. 这种情况只写结论, 并在「定位」里注明"当时的排查过程未记录"
