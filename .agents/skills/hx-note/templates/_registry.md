# 模板注册表

## 现有模板

| 模板 | 文件 | 适用 | 默认 |
|---|---|---|---|
| 兴趣&展望 | [interest-outlook.md](interest-outlook.md) | 从外部素材 (视频/文章/调研) 沉淀出来的知识, 读者是"想了解这个方向"的人 | ✅ |
| 踩坑复盘 | [problem-solution.md](problem-solution.md) | 从本地代码/git 变更/一次实际故障沉淀, 读者是"正在遇到同一个问题"的人 | |
| 可复用规格 | [reusable-spec.md](reusable-spec.md) | 素材本身是一套可照做的做法 (外部项目的实现方式 / 自己刚搭好的约定), 读者是"要照着搭一遍"的人 | |

## 怎么选

问一个问题: **读者读完想干的三件事里, 是哪一件?**

- 想"哦, 原来如此" -> 兴趣&展望。它的任务是让人**有兴趣**。
- 想"我也去搭一个" -> 可复用规格。它的任务是让人**能照着搭出来**。选它的前提是
  素材里有能直接用的东西 (骨架 / 令牌 / 配置 / 脚本 / 复现件); 只有理念没有可运行产物的,
  先用兴趣&展望写原理, 回去补出最小复现再选这一份。
- 想"我的问题怎么修好" -> 踩坑复盘。它的任务是让人**能修好**。

判断不了就用默认模板, 并在对话里说明选了哪个、为什么 —— 由人类推翻。
**不要自己发明新结构**, 要新结构就按下面的方式加一个模板文件。

## 新增一个模板

加**一个文件**, 在上面的表里加**一行**。不改 `SKILL.md`, 不改任何脚本。

模板文件必须写清四件事:

1. **槽位表**: 有哪些槽、每个槽的字数上限、必填还是可选。
2. **每个槽的硬约束**: 能写什么、不能写什么。要能被检查, 不要写"写得生动一些"。
3. **渲染后的骨架示例**: 真实的 markdown, 含真实的标题写法。
4. **这个模板拒绝什么**: 明确写出它不适合的场景, 否则它会被滥用成万能模板。

两条跨模板的铁律, 新模板也必须遵守:

- **槽位名不是标题名.** `引入` `正文` `展望` 是模板内部词汇。渲染出来的标题必须是
  具体的内容标题 —— 页面上出现 `## 正文` 这种字样, 一眼就是机器生成的。
- **所有事实来自 `.hx-info.md`.** 模板决定怎么讲, 不决定讲什么。模板里不许出现
  "可以适当补充一些背景"这类给模型开口子的话。`reusable-spec.md` 的规格段是把
  `.hx-info.md` 里的事实**换成动作**讲, 不是绕开它 —— 新出现的取值同样要先回写那边。
