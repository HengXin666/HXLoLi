# 模板: 兴趣&展望 (默认)

读者是**带着好奇**来的. 任务: 读完想去试一试

这份只留槽位与硬判据. 每条判据的来由与反例在 `shared/voice/impl/outlook-rationale.md`, 盲审判 FAIL 时再读

## 写作顺序 (不许倒过来)

1. 先出分镜 `source/storyboard.md` (格式见 `assets/storyboard-template.md`): 每个 `## 0xNN` 一行, 写清这段要证明的一句话, 以及它需不需要一张结构图. 分镜给人看过再写字
2. 读 `shared/voice/impl/exemplars.md`, 照样本语气只写引入段
3. 按分镜逐段写. 有结构图的段先放图, 再写接住它的一两句话; 没有结构要讲的段只写字. 事实只从 `.hx-info.md` 取

## 槽位表

- **引入**: 上限: 50 字; 必填: 是; 渲染成什么: `# 标题` 下面的第一段, 不带小标题
- **正文段**: 上限: 3 到 6 个; 必填: 是; 渲染成什么: `## 0xNN <名词短语标题>`, 标题 4 到 17 字
- **结构图**: 上限: 不设; 必填: 选填; 渲染成什么: 架构图 / 流程图 / 真实截图, 只在这一段确实有结构要讲时放
- **段落**: 上限: 单段 150 字; 必填: 是; 渲染成什么: 一段只说一件事, 超了就拆
- **可复用物**: 上限: 不设; 必填: 选填; 渲染成什么: 真跑过或有出处的代码块 / 同目录侧车; 没有就不放
- **展望**: 上限: 50 字; 必填: 选填; 渲染成什么: 最后一段的收尾句, 必须是能被反驳的判断; 写不出就不写

## 硬判据 (lint / doctor 会查)

- 引入写的那件事, 在决定写这篇之前就发生过. 没有真实遭遇就写真实动机, **不编**
- 不用 markdown 表格. 对照写成分点 (`- **A**: ...`), 结构关系画成图
- 单段不超过 150 字 (`long-para-hard`)
- 代码块的出处逐块写进 `.hx-mitemite.md` 的「## 代码出处」(doctor 核对); 没有真代码就不放
- 每张图后面紧跟一句话把它接进论点; 不被引用的图删掉
- 不写"参考来源"章节: 站点会从正文链接自动生成
- 论断按来源等级写: T1 直接陈述, T2 写"据 某某", T3 只当线索 (等级定义见 `steps/2-collect/impl/research.md`)

## 这个模板拒绝什么

- API / 配置速查: 那种内容是穷举式的, 直接写进 `docs/`
- 纯故障复盘: 用 `templates/problem-solution.md`
- 没有真实素材的主题: 所有事实都必须能在 `.hx-info.md` 里找到依据
