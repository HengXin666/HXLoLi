# 模板: 可复用规格 (照做型)

读者是**要照着搭一遍**的人. 任务: 拿着这一篇, 在自己的项目里得到同样的结果

默认模板 (`interest-outlook.md`) 讲"这是怎么回事"; 本模板讲"怎么搭出来". **判定用哪份**: 读者读完是想"哦原来如此", 还是想"我也去搭一个"? 后者用这份

## 槽位表

| 槽位 | 上限 | 必填 | 渲染成什么 |
|---|---|---|---|
| 用途 | 60 字 | ✅ | `# 标题` 下面的第一段, 不带小标题. 写清**这套东西用在什么项目上** |
| 触发场景 | 80 字 | ✅ | `## 0x00 用在什么项目上` |
| 契约 | 不限 | ✅ | `## 0xNN <不能变的那几件事>`, 每条带机械判据 |
| 约定 | 不限 | ✅ | 多个 `## 0xNN <已经替你定死的选择>` (骨架 / 库 / 分层 / 状态) |
| 偏好 | 不限 | ✅ | `## 0xNN 写法习惯`, 每条写成可检查的禁令 |
| 可直接拷走的件 | 不限 | ✅ | `## 0xNN 拿去就能用`, 表 + 内嵌侧车 |
| 引用关系 | — | 自动 | 不写章节, 站点在页面底部自动渲染 |

槽位与层级的对应关系、每层写什么、反例, 全部在 `steps/6-derive/impl/reusable-spec.md`. **本文件只写"填哪几个槽", 不重复那边的写法. **

## 硬约束

- **必须有侧车. ** 没有可直接拷走的件的"规格"是散文. 侧车与 `index.md` 同目录: `.tsx` 内联演示页 (默认) / `.html` 侧车 / 复现件 / 骨架组件
- **每条契约都要有判据. ** 判据的形式是"跑什么命令 / 命中哪条规则", 不是"注意别写错". 写不出判据的约束要么补脚本, 要么降级成偏好并说明为什么查不了
- **库只有一个来源. ** 不许出现"也可以用 X 或者 Y". 要保留两个就写出各自的代价
- **版本必须写. ** 前端库的 API 一年一变, 不写版本半年后照着做会失败
- **正文里不许出现"参考官方文档"**  那是把规格的责任推回给读者. 要引就引到具体小节
- **不复述原理. ** 原理在 `.hx-info.md` 的对应块里; 本模板的每一段都应该是**动作**

## 这个模板拒绝什么

- **纯讲解型的素材**: 读者读完只是"懂了". 那用 `interest-outlook.md`
- **没有可运行产物的方法**: 只有理念、没有能跑的东西. 这种素材先回去补最小复现, 补不出来就说明还没真懂 (见 `steps/2-collect/impl/repo.md`)
- **单次故障的排查记录**: 用 `problem-solution.md`
- **API 速查**: 那种内容适合表格与穷举, 直接写进 `docs/`
