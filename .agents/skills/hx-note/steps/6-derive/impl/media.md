# 配图、代码块与演示页

## 先选类型, 再选后端

| 要画什么 | 用什么 | 产物 |
|---|---|---|
| 架构 / 流程 / 分层 / 数据流 | `scripts/hx_drawio.py` | `xxx.drawio.svg` (页面可直接编辑) |
| 需要动效、导览、主题切换的机制图 | `archify` skill | 自包含 `xxx.html` |
| 概念示意 / 封面 / 类比图 | 生图后端 (见下) | `xxx.png` |
| 真实界面 / 实测结果 / 视频关键帧 | 截图 | `xxx.png` |
| 多步演示 | `hx-docs-ppt` skill | `xxx-deck.tsx` 或 `xxx.html` |

**能用 `.drawio.svg` 的场合优先用它**: 矢量、体积小、人类后续能双击改, 而生成的位图
改不动, 错一个字就得重生成。

所有产物与 `index.md` **同目录**。

## drawio.svg

```bash
# 自检 (先跑这个确认环境没问题)
uv run .agents/skills/hx-note/scripts/hx_drawio.py --demo -o /tmp/demo.drawio.svg

# 正式生成
uv run .agents/skills/hx-note/scripts/hx_drawio.py spec.json \
  -o "ai-docs/.../NNN-标题/pipeline.drawio.svg"
```

spec 只支持**分层左右布局**, 这是刻意的限制 —— 自由布局必然画崩:

```json
{
  "title": "可选, 左上角标题",
  "columns": [
    {"title": "列标题", "nodes": [{"id": "a", "label": "节点文字", "accent": true}]},
    {"title": "下一列", "nodes": [{"id": "b", "label": "..."}]}
  ],
  "edges": [{"from": "a", "to": "b", "label": "可选"}]
}
```

约束:

- 文件名**必须**以 `.drawio.svg` 结尾, 否则站点不会当成可编辑图 (脚本会拒绝)。
- 节点文字最多 3 行, 超出被截断 —— 说明该拆节点了, 不要塞长句。
- **边的 `label` 控制在 6 个字以内.** 列间距只有 96px, 长标签会压到相邻节点的边框上。
  想说清楚就在正文里说, 不要往图上堆字。
- 一张图最多 3 列 × 4 行。再复杂就拆两张, 或者改用 `archify`。
- 同列节点之间的边画成竖直线, 跨列画正交折线。想要别的走线请改脚本而不是手改产物。

正文引用: `![<说明> ##w800##](pipeline.drawio.svg)`

## 生图后端 (可插拔, 不要硬编码)

正文里需要概念示意图时, 按下面顺序**探测**, 用第一个可用的:

1. 会话里已挂载的图像生成能力 (如 `gpt-img2`、多模态内容生成类 skill / MCP 工具)。
   **先确认它真的在当前工具列表里**, 不要凭名字直接调。
2. 人类手动提供 (把图丢进笔记目录)。
3. 降级: 改用 `.drawio.svg` 表达同一个意思。

三条都不可用时: **不要空着一个图位, 也不要写"此处应有图"**。把那一段改写成代码块或
分点说明, 并在对话里告诉人类"这一节本来想配示意图, 当前环境没有可用的生图后端"。

新增一个后端 = 在上面的顺序表里加一行, 不改任何脚本。

## 每张图的三条硬要求

1. **被引用**: 图后面紧跟一句话把它接进论点 ("上图里第二层就是…")。
   没有这句话的图等于装饰, 删掉。
2. **能独立看懂**: alt 文字写清这张图在说什么, 不要写 `架构图` 这种废话。
3. **宽度显式**: `##w800##` 是常用值; 需要圆角 `##r10##`; 要原始尺寸用 `####`。
   不写宽度在宽屏上会糊成一片。

## 代码块

围栏标注写成 ` ```lang [组名-标题] `。**同前缀的块会被合并成一个 tab 切换组**, 这是最容易
踩的坑: 两段无关的代码用了同一个前缀, 会被并进同一个切换器, 读者只能看到其中一个。

```markdown
对照同一件事的两种写法 -> 同前缀, 会渲染成两个 tab:

```cpp [切换成本-无栈]
```cpp [切换成本-有栈]

无关的另一段代码 -> 换前缀:

```cpp [调度器-投递]
```

其它约束:

- 片段要**最小可跑**, 不要贴整个文件。
- 注释用中文口语, 和正文同一个人在说话。
- 报错、终端输出用 ` ```text `, 保持原样不整理。
- 需要在页面上直接编辑的片段用 ` ```cpp vscode `。

## 演示页

`[标题 ##PPT##](x-deck.tsx)` (React 内联, 跟随站点主题) 或
`[标题 #ppt](xxx.html)` (自包含单文件)。两者的产出规范以 `hx-docs-ppt` 为准,
本文件不重复。

侧车产物与 `index.md` 同目录; `.tsx` 形态新增后要跑 `npm run decks`。

## 数学与图表的其它语法

Mermaid (` ```mermaid `)、KaTeX (`$...$` / `$$...$$`)、GitHub Alerts、B 站视频嵌入等
平台语法以 `hx-note 的步骤 5` 的 `references/hxloli-md.md` 为准。

**Mermaid 谨慎用**: 它在页面上是自动布局, 结构一复杂就变丑, 而且人类改不动。
需要人类后续维护的图一律用 `.drawio.svg`。
