# 4 align — 人类认不认这些知识点

## 只做这一件事

跟人类对齐**内容**. 拿到两样

1. 人类确认 `.hx-info.md` 的知识点**对**且**够**
2. 侧重与取舍: 同一份素材有多种讲法时选哪种, 牺牲什么

**不谈放哪里. ** 目录归属是步骤 5 的事, 在这里提会把话题带偏. 人类主动问「放哪」时, 回答「先把知识点定下来, 路径我下一步给你三个候选」

## 产物

`.hx-mitemite.md` (答题卡)

## 实现

| 要解决的问题 | 读 |
|---|---|
| **怎么问**  一次一题、锐化模糊词、用场景压测、与已有产物对照 | `impl/grill.md` (**这份先读**, 它改写自 grill-me) |
| 问什么  design-tree + frontier 算法 | `impl/frontier.md` |
| 验收条款与术语表的落盘格式 | `../../assets/goal-template.md` |

**一次只问一题, 答完再问下一题. ** 我们原来的做法是把整个 frontier 一次抛出去  实测的后果是人类扫读、挑着答、或者照抄推荐. 原话是「他就让我在那里乱说」. 需求对齐是这个流程里唯一值得慢下来的地方

## 做法

每轮问**当前整个 frontier**, 每题附推荐答案, 然后**停下等人类**

一次只问当前 frontier, 不要批量抛问卷. 有半成品再问, 不要问空问题

### 必须把问题端到人类面前 (这一步最容易做错)

**只写进答题卡不算问过. ** 答题卡住在 `ai-docs/.hx-staging/<slug>/` (点开头目录) 里, 文件名也是点开头  实测普通 `ls` 看不见它, 本地开发 UI 也跳过点开头项, 所以**暂存区没有任何界面**. 人类不会自己发现那张卡

所以每轮出完题, 必须做这两件事, 一件都不能省

```bash
uv run .agents/skills/hx-note/scripts/cli/flow/hx_flow.py brief --slug "<slug>"
```

1. 跑上面的命令, 它会把**待答的题 / 被审对象在哪 / 怎么作答**打成一屏
2. 把这一屏**贴进对话**里给人类, 然后停下等回答

### 「推荐答案」不是答案

推荐答案放在问题里 (以 ➡️ 开头), 它的作用是让人类能**否决一个具体主张**而不是从零思考. **它不是人类的答复. ** 把推荐答案当答复直接推进, 等于这一步没做  实测就是这么发生的: 全库 16 份答题卡里 11 份的 `**A**:` 从未被填过, 包括已发布的笔记

人类不在线时只有两条路: 等, 或让人类**明确**授权按推荐执行 (授权写进 `--note`)

## 过关条件

答题卡里**每一题的 `**A**:` 都被人类填过**, 且 frontier 为空

`done align` 会机械检查这一条: 有未答的题就拒绝推进; 若这次是靠 `--force` 过的, `place` 会再拦一次 (那时是把未审内容铺上站点的最后一道口子)
