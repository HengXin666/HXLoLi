# 定制化沉淀 (需登录 / 特殊解析)

适用于登录墙后的页面、需要特定解析方式的产物 (如 GPT 对话记录)、私域文档、需要 cookie 的站点

## 第一原则: 显式声明, 不伪装

来源不是公开网页时, **必须在 provenance 与对话里说清怎么拿到的**. 不要在正式笔记里把它伪装成「公开文章引用」, 也不要伪造一个可点开的链接

## 三条路径, 按推荐顺序

1. **官方导出 / API**  最稳定、最不敏感. 对话记录用官方分享链接或导出文件
2. **本机已有登录态**  只用人类**已经授权**的会话, 不新建登录
3. **人类直接提供文本**  最省事

**禁止**: 自动登录、替人类输密码、绕验证码、伪造身份. 需要凭据时停下来问人类.

## 人类踩过的坑

- **模型输出不等于事实**: 模型会自信地编造 API、版本号、数字. 可验证的论断**必须外部复核**, 核不了就标`[不确定]` 或删掉
- **保留角色结构**: 区分「人类提的约束」与「模型给的回答」, 不要混成一段叙述
- 探索过程有价值 (试错、被否决的方案), 但要重写成「问题 → 候选 → 为什么选它」
- **脱敏**: token、账号、内网地址、私人信息; 截图同样打码

## provenance 记录格式

写进对话, 不进正文

```
来源类型: 登录态页面 / 官方导出 / 人类提供文本
获取方式: <具体工具与命令, 或 由人类粘贴>
获取时间: <日期>
可信度备注: <是否截断 / 是否只拿到部分 / 模型输出是否已复核>
```
