# 调研模式沉淀

**与单篇定向沉淀的区别: 先建证据, 再下结论。**

## 固定路线

1. 把「调研 X」收敛成可回答的具体问题 (范围、时间、要对比的维度)。太宽就先问人类。
2. 多源采集用 `wide_research` (自带来源账本与不确定度披露); 单点补充用 `argo_search` / `argo_fetch`。
3. **先出结论表给人类确认, 确认后再写笔记。** 表列: 结论 / 依据 / 可信度 / 反例。

## 证据分级 (写笔记时必须能区分)

| 级别 | 写法 |
|---|---|
| 多源一致 | 正常陈述 |
| 单源未复核 | 明确写「据 <来源>」 |
| 由证据推出的判断 | 标为个人判断 |
| 查不到 | 写「未找到公开资料」, 不要填空 |

## 人类踩过的坑

- **厂商宣传不是事实**: README / 官网 / 发布会说法标为「官方声称」, 与第三方评测分开。
- **结论要带版本号或时间点**, 否则半年后就是错的。
- 中间产物 (原始抓取、对比表、来源清单) 放 `research-output/` —— 那是**过程目录, 不是交付物**。
  正式交付永远是 `ai-docs/` 下的笔记, 不要把报告丢在 research-output 里当成品。

## 反模式

只列不判 (罗列十个项目却不给结论); 均等化对待 (玩具项目和成熟项目并列, 必须标维护状态);
只收支持预设的材料 (要主动找反例)。
