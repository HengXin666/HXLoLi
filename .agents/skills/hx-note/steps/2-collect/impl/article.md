# 公开文章 / 网页沉淀

## 固定路线

1. `argo_fetch` 抓正文 (HTTP 优先, 遇 Cloudflare/JS 渲染自动升级; `--focus` / `mode=extract` 只取正文)。
   抓不到再找镜像或译文 —— 记得在 provenance 里写明**实际读的是哪个 URL**, 不是原始 URL。
2. 三个产物的固定形态: `material.md` 每条带定位 (小标题名或原文短引) / `provenance.md` 写来源与可信度。
3. 重述, 不摘抄。

## 人类踩过的坑

- **只抄结论最危险**: 文章的结论脱离它的前提就是错的。写的时候把前提一起带上。
- **论证链比结论值钱**: 它要解决什么问题 → 主张是什么 → 依据是什么 → 边界在哪。四步走完再落笔。
- **抓下来的正文带大量导航/推荐噪声**, 提炼时容易漏掉真正的署名与发布时间。
- 时效性内容 (工具用法、版本号、API 名) 标注「截至 <时间>」, 否则半年后就是错的。
- 需要登录或特殊解析 -> 转 `custom.md`。

## 判断值不值得沉淀

三个问题答不上来就别写: 半年后还成立吗? 比存个书签多提供了什么? 和已有笔记重复吗?
