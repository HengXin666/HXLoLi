# 公开文章 / 网页沉淀

## 固定路线

1. **抓正文**. 按下面的探测表从上往下, 用第一个在当前会话里**真的可用**的
2. **回溯一手**. 读到的是二手文章时, 顺着它的引用找原始规范、官方文档、源码或论文, 一起采进来. 找不到写进 provenance 的已知缺口
3. 三个产物的固定形态: `material.md` 每条带来源编号与定位 / `provenance.md` 每个来源带等级 (T1 到 T3, 定义见 `research.md`)
4. 重述, 不摘抄

## 抓取探测表

用能力描述选工具, 不认工具名. 换一个 agent 来跑, 这张表给出的路线也一样

| 顺序 | 能力 | 判据 |
|---|---|---|
| 1 | 会话里已挂载的网页抓取工具 (能返回正文文本的那一类) | 先确认它在当前工具列表里, 不要凭名字调 |
| 2 | `curl -sL <URL>`, HTML 再抽正文 | 返回 200 且正文里能搜到标题 |
| 3 | 官方的纯文本或原始格式版本 (RFC 的 `.txt`, 仓库的 raw 文件) | 同上 |
| 4 | 镜像或译文 | 在 provenance 里写明实际读的是哪个 URL |
| 5 | 都不行 | 转 `custom.md` |

## 人类踩过的坑

- **只抄结论最危险**: 文章的结论脱离它的前提就是错的. 写的时候把前提一起带上
- **论证链比结论值钱**: 它要解决什么问题, 主张是什么, 依据是什么, 边界在哪. 四步走完再落笔
- **抓下来的正文带大量导航/推荐噪声**, 提炼时容易漏掉真正的署名与发布时间
- 时效性内容 (工具用法、版本号、API 名) 标注「截至 <时间>」, 否则半年后就是错的
- 需要登录或特殊解析 -> 转 `custom.md`

## 判断值不值得沉淀

三个问题答不上来就别写: 半年后还成立吗? 比存个书签多提供了什么? 和已有笔记重复吗?
