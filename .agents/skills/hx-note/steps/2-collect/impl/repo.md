# 外部源码项目 (前端 / UI 实现 / 单文件 HTML·TSX)

学一个外部项目**怎么做出某个效果**。素材是代码, 不是文章 —— 所以采集方式是**读实现 + 跑起来看**,
两者的结论都算素材。

## 铁律: 只读, 且只往临时目录写

这条排在最前面, 因为它是本路径唯一会**破坏别人项目**的地方。

- **不改被学的项目一个字节。** 不编辑、不格式化、不"顺手清理"、不提交、不切分支。
  需要探索就在**它的副本**上做, 副本放临时目录。
- **克隆到临时目录, 不要克隆进笔记仓库。** 目录用 `/tmp/hx-repo-<slug>/`。
  默认 `--depth 1`; 只学当前实现的话, 完整历史没有用。
- **产物只有两种**: 暂存区的 `source/` 与最终那一篇 `index.md`。
  不在 `ai-docs/` 下留任何"成品项目目录" —— 读者要的是一篇能照着做的说明, 不是一个仓库。
- **依赖装不装?** 只在副本里装, 且只在真需要跑起来看时才装。`node_modules` 绝不进笔记目录。

反例 (真实踩过): 学一个前端项目的 UI, 最后在笔记仓库里留下了一个演示工程的目录树。
那个目录既不是笔记、也没人维护, 只在 `git status` 里当噪声。

## 固定路线

1. **先看目录结构与构建方式**, 别急着读组件。
   `package.json` 的 `dependencies` 决定它用了什么栈; `vite.config` / `next.config` 之类决定怎么跑起来。
2. **跑起来看。** 视觉效果必须亲眼见到 —— 读 CSS 猜不出"好看"在哪。
   起在 3000 以外的端口, 别占用笔记站点自己的端口。
   ```bash
   git clone --depth 1 <url> /tmp/hx-repo-<slug>
   cd /tmp/hx-repo-<slug> && (pnpm i || npm i) && (pnpm dev || npm run dev)
   ```
3. **再回去读实现。** 现在你知道要看什么了: 那个具体效果是哪几行产生的。
   用截图 + 源码定位配对, 每张图旁边写清它对应哪个文件。
4. **抓住能复用的那一层。** 外部项目里 90% 是它自己的业务代码, 只有一小部分是可迁移的做法
   (配色变量怎么组织、动效怎么触发、布局怎么分层)。**只采那一层。**
5. **能复现就复现。** 用最小的单文件 HTML/TSX 把它重做一遍, 放进暂存区 —— 复现不出来的
   说明还没真懂。
6. **在步骤 6 决定它的去向。** 复现件有两条出路, 都要走: (a) 验证阶段的证据留在
   `source/`; (b) 若它承载的正是**可迁移的那一层** (骨架 / 令牌 / 接线), 就提升成正式
   侧车 (与 `index.md` 同目录、正文里内嵌), 见 `steps/6-derive/impl/reusable-spec.md`。
   **只留在暂存区等于做完就埋** —— 暂存区是点开头目录, 读者看不到, 也不会被构建发布。

## 前端项目特有的采集点

| 看什么 | 具体找 | 记成什么 |
|---|---|---|
| 设计令牌 | `theme` / `tokens` / CSS 变量 / tailwind config | 变量名 + 值 + 它们之间的关系 |
| 动效 | `transition` / `animation` / `@keyframes` / framer-motion 用法 | 触发条件 + 时长曲线 + 它想让人感觉到什么 |
| 布局骨架 | 容器组件 / AppShell / 栅格 | 分层关系 (谁包谁), 不要抄长宽数值 |
| 交互反馈 | hover / focus / loading 态 | 状态有哪些, 各自什么时候出现 |
| 色彩 | 中性色梯度 / 强调色用法 | 用途而不是色值清单 |

**抄的是做法, 不是数值。** 记「主色只用在当前可操作项上」比记「主色是 #4A90D9」有用得多。

## 关于 HTML 与 TSX 两种形态

这个 skill 里 `.html` / `.tsx` 本来是**产物**形态 (演示页侧车, 见 `steps/6-derive/impl/tsx-deck.md`)。
但它们是**素材**形态时同样成立, 而且很多时候是最方便的:

- **单文件 `.html`** —— 一个链接就能看效果的项目 (CodePen / 官网 demo / 组件库 playground)。
  采集就是抓下来 + 截图 + 标出关键几行。**它自带全部资源**, 不需要装依赖。
- **`.tsx` / `.jsx`** —— React 生态的做法在这类文件里最清楚 (组件粒度、状态放在哪、怎么组合)。
  读的时候重点看**组件边界怎么划**, 而不是它渲染出什么。
- **最小复现也用它们**: 一个自包含的 `.html` 或 `.tsx`, 能直接贴进笔记正文或当侧车。

## 人类踩过的坑

- **不要按目录树逐个文件总结。** 那是把源码抄一遍, 没有人会读。只写"做出这个效果需要哪几件事"。
- **视觉好看 ≠ 可迁移。** 先问"它是靠一套方法做出来的, 还是靠作者的手感"。前者能学, 后者写不出。
- **帧率与性能的说法要有实测**(录屏帧数、DevTools 数据), 不要凭"看起来很流畅"下结论。
- **依赖版本要写进 `provenance.md`** —— 前端库的 API 一年一变, 不写版本, 半年后照着做会失败。
- **许可证**: 抄做法没问题, 但整段代码搬进笔记前先看 LICENSE, 并在正文标注来源。

## 适合沉淀的信号

一个效果让你想"哦原来还能这么做"; 某个做法能在你自己的项目里直接搬; 你踩过同类的坑
(比如动画掉帧、布局在移动端崩了), 而它给了另一种解法。

## 过关条件

`material.md` 里每个要点都能指回 `provenance.md` 里的来源, 且**至少有一张实跑截图 + 一处源码定位**。
