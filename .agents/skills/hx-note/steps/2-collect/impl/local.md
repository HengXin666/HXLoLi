# 本地变更沉淀 (代码 / git / 配置)

## 固定路线

1. `git log` / `git diff` / `git show <sha>` 定位改了什么。**未提交的改动同样可以沉淀。**
2. **打开源码确认实际行为。禁止只凭 commit message 或 diff 摘要推断实现细节。**
3. 正文里给出 commit 链接: `[\`50c931c\`](https://github.com/<owner>/<repo>/commit/<sha>)`。

## 人类踩过的坑

- **踩坑才是核心价值**: 只写「做了什么」等于让人自己看 diff。要写清「哪一步本以为对、实际错在哪、怎么发现的」。
- **区分事实与判断**: 代码现在是这样 (事实) vs 我认为该这样 (判断), 不要混在一句里。
- 本地变更最容易写成只有作者看得懂的流水账。动笔前按步骤 4 确认读者是谁。
- 私有仓库路径、内网地址、凭据不进正文。

## 适合沉淀的信号

同一个坑踩了第二次; 做了非显然的取舍、半年后自己会忘记理由; 踩坑过程能推广到别的项目。

反之, 单纯格式化、依赖升级、配置同步, 不值得单独成篇。
