# 标题、tag、可见性与双链

> [! WARNING]
> 本文件**不再**规定成文结构. 原先的"开头设问引入 / 结尾拓展升华 / 标注个人判断"
> 三件套已废除  现有 29 篇 ai-docs 篇篇照此执行, 结果这三件套本身成了最明显的
> AI 指纹 (设问式开头与 `个人判断: 我倾向于认为…` 结尾在全库逐字重复).
>
> 段落结构以 `hx-note 的步骤 6` 的 `templates/` 为准; 文风判据以 `hx-note 的 self-check` 为准.
> 本文件只留平台层面的三件事: 标题与 tag、可见性划分、双链写法.

## 一、标题与 tag

- 标题: 凝练且专业, 允许一个副题 (如 "深入理解Cloudflare过盾原理: 无需AI从零实现CFTurnstile绕过")
- 人类改过标题后**只给建议, 不擅改**
- tag: 先跑 `hxloli_tags.py suggest "<词>"` 查外挂注册表 `ai-docs/.hx-tags.toml`, 能复用就复用; 都不合适才新增, 一次新增不超过 2 个 (见 SKILL.md 的 HXLoLiTag 一节)
- frontmatter 的 `title` / `tags` 可在 `makeDoc.py` 产物基础上修正, 但不要手写整个文件绕过模板
- `index.md` 与同目录 `.hx-info.md` 的 `hxid` 与 `title` 必须一致  它们是同一篇笔记的两个面

## 二、章节编号

主章节用十六进制序号, 需要子项时改用中文嵌套, **两套不要混用**

```markdown
## 0x00 <具体内容标题>
## 0x01 <具体内容标题>
## 0x02 <具体内容标题>
```

**从 0x00 连续编下去, 不要跳号. ** 旧流程在正文后空一段、把"参考来源"固定写成 `0x0A`, 于是正文最后一段与 0x0A 之间永远缺几个号, 读者会以为漏了内容. 那个章节现在已经取消(引用关系改由页面底部的方框渲染), 所以也没有跳号的理由了

```markdown
## 一、title1
### 1.1
#### 1.1.1
```

标题里写**具体内容**. 出现 `## 正文` `## 核心结论` `## 关键细节` 这类模板残留字样, 一眼就是机器生成的

## 三、引用关系由站点自动渲染, 不要手写

**正文末尾不写"参考来源"章节. ** 站点会在每个笔记页面底部自动渲染一个方框

```
┌ 本文引用 (3) ┬ 本文被引用 (1) ┐
│ · xxx 笔记                      │
│ 站外来源 (2)                    │
│ · modelcontextprotocol.io       │
└─────────────────────────────────┘
```

数据由 `plugins/note-references-plugin.mjs` 在构建期从正文的链接里抽出来, 分三类: 本文引用 (站内出边) / 本文被引用 (站内入边) / 站外来源

所以要做的只有一件事: **在正文里正常用链接**. 方框自己会显示

为什么不手写: 手写的参考来源读者读完就忘, 而且看不出方向 (谁引了谁); 它还要人工与正文同步, 必然漂移; 更分不出站内与站外. 它本来就是一张图, 该由机器抽

来源不可公开访问时 (私有对话、内网文档), 仍在正文里**一句话说明**来源性质, 不要伪造可点开的链接. 这种来源不会出现在底部方框里 (它不是 URL), 所以那句说明是必要的

## 四、读者可见 vs 仅审核可见 (铁律)

一篇笔记有两个产物, 加上过程产物一共三类去处, 不要混

| 内容 | 唯一去处 |
|---|---|
| 面向读者的文章 | `index.md` |
| 面向知识库的原子知识点 | `.hx-info.md` (同目录, 见 `hx-note 的步骤 3`) |
| 需要人类 review / 拍板的点、局限与待办 | `.hx-mitemite.md` (见 `hx-note 的步骤 4`) |
| 生成过程、工具链、脚本命令、本地路径、验证步骤、ASR 转写、provenance、盲审报告 | `ai-docs/.hx-staging/<slug>/`, **不进笔记目录** |
| 引用过的外部来源 | 正文里的正常链接 (底部方框自动渲染) |

成稿自检: 假装自己是第一次点开这篇文章的读者  任何需要内部人才懂的操作细节、任何打断阅读的审核/待办/局限提示, 都要移出 `index.md`

## 五、双链写法

站内笔记互链有两种形态, 不要混用

```markdown
跨文章 (推荐, 目录搬家后链接不断):
参见 [DSH Agent Loop 源码剖析](hxid:hx-1a2b3c4d) 讲事件循环怎么驱动每一步.

同目录内:
参见 [细节研究](./细节研究.md).
```

- 跨文章一律用 `hxid:` 形式 (`hxid` 由 `makeDoc.py` 创建时生成), **不要写死相对路径**  后续重分类时链接不会断. 移动过目录后跑 `hx_docs_id.py resolve --write` 重算
- `docs/` 与 `ai-docs/` 是两棵独立文档树
- **链接文字要说明那篇讲什么**, 与本文什么关系. 不要写"点击这里"
- 外链 (GitHub commit / 原文 / 视频) 放正文行内 + 末章汇总; GitHub 项目类笔记应关联对应 commit URL
