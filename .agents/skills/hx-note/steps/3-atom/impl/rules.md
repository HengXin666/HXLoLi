# 原子知识点写法细则

## 一、标题必须是答案, 不是话题

这是整份规范里唯一真正决定检索质量的一条。

切片器按标题切块。如果标题是话题, 切出来的块开头是一个问句或一个名词, 检索时
无法判断这块讲了什么; 如果标题是结论, 块本身就是一条可用的答案。

```markdown
坏: ## 关于无栈协程的切换成本
坏: ## 切换成本                     <- 谁的切换成本?
好: ## 无栈协程的切换成本等同于一次函数调用, 有栈协程等同于用户态线程切换
```

判据: **把这一行单独发给一个没读过全文的人, 他能不能理解?** 不能就重写。

**不要给标题加编号** (不写 `## K01 ...`, `## 知识点1` 之类)。理由: 没有任何消费方 ——
检索靠标题文本本身, 不靠序号; 而序号要求人工维护, 增删一条就要重排后面全部, 是纯负担。
需要指代某一条时, 引标题里的一小段文字即可, 那比 `K07` 更好懂。

## 二、每块自包含

一块知识点会被单独检索出来, 它的上下文**不会**一起出现。所以块内:

- 术语首次出现写全称: 写 `无栈协程 (stackless coroutine)`, 不写 `它`。
- 不用代词指回别的块: 不写 `上面提到的那种方式`, 直接重复写出名字。
- 不依赖上一块的前提: 需要前提就在本块重述一遍。宁可重复, 不要悬空。
- 不写序数位置: 不写 `第二种方案`, 写 `基于 handle 恢复的方案`。

```markdown
坏:
## 它的开销更小
- 因为上面说的原因, 所以这种方式更快.

好:
## 无栈协程不需要独立栈, 因此单个协程的内存开销约为一个协程帧的大小
- 无栈协程把局部状态编译进协程帧, 帧大小在编译期确定.
- 有栈协程需要为每个协程预留一段栈空间, 默认值通常远大于一个协程帧.
- 依据: 原文"无栈指可挂起/恢复的函数, 有栈协程则相当于用户态线程"一节.
```

## 三、一块只放一件事

一块里出现"另外""同时还""顺便"就说明该拆了。拆的代价是零 (多写一个 `## ` 小节),
不拆的代价是检索时这块永远只能被一半的问题命中。

## 四、禁止清单 (`hx_voice.py lint --profile atom` 会拦)

| 禁止 | 为什么 |
|---|---|
| 配图 `![...]` | 这份文件是喂给检索的纯文本, 图片是噪声. 配图属于 `index.md` |
| 人称 (我 / 我们 / 你可以 / 大家) | 检索命中的是知识, 不是谁在说话 |
| 设问、反问 | 铺垫是给人类看的, 对检索只有污染 |
| 递进连接词开头 (首先 / 其次 / 因此 / 此外 / 而且) | 说明这块依赖上下文, 违反自包含 |
| 模糊限定 (可能 / 也许 / 大概 / 似乎) | 确定就断言, 不确定就写 `[不确定]` 并说明为什么 |
| 破折号、"不是X而是Y"、套话 | 与 `index.md` 同一套判据 |
| 引入段、过渡段、总结段、升华段 | 这份文件里**没有**这些章节 |

## 五、"依据" 不是可选项

每块的最后一条固定是 `- 依据: <定位>`。定位要能让人**一次**翻到原处:

| 素材类型 | 合格的定位 |
|---|---|
| 视频 | `00:12:34 附近` |
| 文章 | 小标题名 / 原文短引 |
| 代码 | `文件:函数` 或 commit hash |
| 实测 | 测了什么、结果是什么 |

写不出依据的知识点, 说明它是你推断出来的 —— 要么补证据, 要么删掉, 要么标
`[不确定]` 并在「边界」里说明这是推断。

## 六、「边界」章是质量的分水岭

只写结论的知识库会害人: 结论脱离前提就是错的。这一章必写三类内容:

1. **失效条件**: 这些结论在什么情况下不成立。
2. **已知反例**: 素材里提到或你查证到的反例。
3. **不确定项**: 每一个 `[不确定]` 都要在这里说明为什么不确定、怎么才能确认。

素材本身没谈边界时, 写 `- 原素材未讨论边界, 以下结论仅在其给定前提下成立: <前提>`。
这比留空诚实。

## 七、与 `index.md` 的单向关系

```
.hx-info.md  ---(派生)--->  index.md
     ^                          |
     +---(新事实必须先回写)------+
```

- `.hx-info.md` 是**唯一事实源**。
- `index.md` 只允许换一种说法讲这里已有的东西, **不允许新增技术论断**。
- 写文章过程中发现了新事实 (新的数字/API/因果), **先补进 `.hx-info.md`** (且要有依据),
  再在文章里用。顺序反了就会出现"文章里有、知识库里没有"的悬空事实。
- 定稿前的保真盲审就是在查这条 (见 `hx-note 的 self-check`)。

## 八、检查

```bash
uv run .agents/skills/hx-note/scripts/hx_voice.py lint <dir>/.hx-info.md
```

profile 会按文件名自动选成 `atom`。E 级命中必须清零。

lint 通过之后再人工确认两件正则查不出来的事:

1. 每个 `## ` 标题单独拿出来是否成立。
2. 每块是否真的只讲一件事。
