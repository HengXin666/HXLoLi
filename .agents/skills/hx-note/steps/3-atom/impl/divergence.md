# 发散: 从素材里造出素材没有的东西

## 这一步解决什么

模型读一份素材, 默认行为是**复述** —— 它把素材的句子换一种说法, 加几句评价, 交差。
这不是能力不足, 是**没有被要求发散**。"请发挥创造力"这种话不产生任何作用:
模型面对空白的"还能想到什么"只会产出感想 (「这体现了设计者的用心」),
而感想是不可验证的, 也就没有价值。

所以这一步不给要求, 给**算子**: 一组具体的、每次都能照着执行的问题。
算子把"发散"从灵感问题变成**执行问题** —— 每一步做什么是确定的, 产出什么由素材决定。

## 什么时候执行

步骤 3 的第一件事, **在写 `.hx-info.md` 之前**。产物是 `source/divergence.md`, 写进暂存区
(不搬进笔记目录, 见 `steps/9-land/impl/gates.md`)。

**只有素材是"一套做法 / 一套规范 / 一个实现"时才跑**。单纯的资讯、事件、
观点类素材没有可发散的结构, 直接写原子知识点。

## 四个算子 (每个都必须至少试一次)

### 一、换轴: 素材说的这条, 换个维度还成立吗

素材给的往往是一条**具体的**规则。做法是把它抽成**它所属的那一类**, 再看同一类里
还有哪些地方在遵守同一条规律。

    例 (素材: "颜色透明度只允许十个固定档位"):
      抽成类 -> 连续量被离散成固定档位
      同类检索 -> 间距是不是也分档? 圆角是不是也分档?
      产出 -> 若间距与圆角也分档, 则这是一条**元规则**:
              "任何连续量都要先离散成有名字的桶", 而不是三条互不相干的规则。

判据: **同一规律在素材里至少出现两次**才算抽对了。只出现一次, 那是这条规则本身, 不是元规则。

### 二、跨源并联: 两条独立的说辞, 是不是同一件事

找素材里两条**分处不同章节、看不出关系**的规则, 问它们能否被**同一条原理**解释。
解释得通时, 得到的是"为什么", 而素材只给了"是什么"。

    例 (素材: A "线条统一 1px" + B "零阴影, 层级靠边框叠层"):
      并联 -> 若层级只能靠边框与叠色表达, 那边框就成了唯一的层级载体;
             载体一旦加粗, 就混进了强度信息, 与叠色的层级手段打架。
      产出 -> "为什么必须 1px" 的理由。素材只说"是 1px"。

判据: 并联出的原理**必须能反推出两条原始规则**。推不出, 就是硬凑。

### 三、迁移: 把这条搬到我自己的项目 / 我认识的另一个东西上

素材里的做法在它**自己的语境**里成立。这一步问: 搬到我的语境还成立吗?
**这一步的产出必须是可实测的, 不是感想。**

    例 (素材: "卡片默认零阴影"):
      迁移 -> 我自己的演示页系统 (hxdeck) 是不是零阴影?
      判据 -> 查 `src/hxdeck/` 下的 CSS 有没有 shadow 声明; 有就说明两套规范在这里不一致。

判据: 必须给出**可执行的检查动作** (查哪个文件 / 跑什么命令 / 看哪个数字)。
给不出检查动作的, 降级为猜测, 按下面"分流"处理。

### 四、拆代价: 这个取舍的付款人是谁, 什么时候付款

**素材几乎从不写自己的代价** —— 它写的是结论。代价要自己推: 这条规则放弃了什么、
谁会在什么时候为此付出成本。

    例 (素材: "只允许十个透明度档位"):
      代价 -> 无法表达 12% / 35% 这种中间值
      付款人 -> 做禁用态、悬停微调的人
      付款时机 -> 第一次遇到"用 /10 太重、/5 太轻"的视觉微调

判据: **付款人必须具体到某类任务**, 不能写"开发者"、"用户"这种空话。

## 产出量与去向

配额 (硬要求, 不是建议):

- 每个算子**至少试一次**;
- 至少产出 **4 条**标为 [素材没有] 的条目;
- 每条 [素材没有] 必须带判据; 给不出判据的**不算数**, 按"猜测"另记。

产出分三路走, 每条都要明确标出去哪一路:

| 产出 | 去向 |
|---|---|
| 判据成立 (实测过或逻辑上可推) | 进 `.hx-info.md` 的一个 `## ` 块, **依据写自己的验证方式** |
| 判据不成立 (推测被证伪) | 进 `.hx-info.md` 的「边界」章, 当已知反例 |
| 给不出判据 | 标 [不确定] 并在边界章说明卡在哪; **不许当结论写进正文** |

**依据可以是你自己的验证。** 这条容易漏: 算子产出的新知识点在素材里没有, 所以依据
不可能是"素材第 N 节"。写成"实测: 查 `src/hxdeck/` 的 CSS 无 shadow 声明"就是合格依据。

## 反模式 (这几条都是模型最容易产出的)

| 反模式 | 例子 | 为什么不收 |
|---|---|---|
| 感想冒充洞察 | 「这套设计体现了对细节的极致追求」 | 不可验证, 也不可反驳 |
| 换个说法当新发现 | 把"1px 统一"重写成"所有线条保持一致的粗细" | 零信息增量 |
| 万能结论 | 「任何规范都要保持一致性」 | 适用一切 = 什么都没说 |
| 无判据的迁移 | 「这套思路应该也能用在后端」 | 给不出检查动作就是空话 |
| 替原作者辩护 | 「作者显然考虑到了 X」 | 无法验证的意图推测 |

判据统一成一句: **这条产出, 素材里能直接找到吗?** 找得到 -> 删掉, 它不是发散;
找不到 -> 再问一句"能不能被证伪", 不能 -> 也删掉。

## 与后续步骤的关系

- 发散产出的全部进 `.hx-info.md` —— **这一步不写正文**。正文怎么讲是步骤 6 的事。
- 保真盲审 (步骤 8) 会核对正文有没有偏离 `.hx-info.md`。**发散出来的结论只要进了 `.hx-info.md` 并带了
  自己的依据, 就是合法事实源**, 盲审不会拦; 反过来, 只写进正文而没进 `.hx-info.md` 的会被拦。
- 因此顺序不可省: 先发散 -> 再落盘 -> 再派生。跳过这一步直接写, 得到的就是一份复述稿。
