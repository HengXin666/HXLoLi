# 3 atom — 哪些是知识点

## 只做这一件事

写 `.hx-info.md`: 面向知识库的纯原子知识点

**这一步不要想文章怎么写. ** 想文章的那一刻就会开始铺垫, 而铺垫是知识库的污染物

## 顺序: 先发散, 再落盘

**先跑发散算子, 再写 `.hx-info.md`. ** 顺序不可换

    素材 ──(算子)──> source/divergence.md ──> .hx-info.md

不跑算子的直接后果是**复述**: 模型读一份素材的默认行为就是把它的句子换一种说法. "请发挥创造力"不解决这个问题  它只会产出不可验证的感想. 解法是给**算子** (一组可执行的问题), 不是给要求. 见 `impl/divergence.md`

只有素材是"一套做法 / 一套规范 / 一个实现"时才跑; 纯资讯类直接写

## 产物

- `ai-docs/.hx-staging/<slug>/source/divergence.md`  发散记录 (过程产物, 不搬进笔记目录)
- `ai-docs/.hx-staging/<slug>/.hx-info.md`  每块一个 `## <完整结论句>`, 末条固定是`- 依据: <能一次翻到原处的定位>`, 末尾有「边界」章

## 实现

| 要解决的问题 | 读 |
|---|---|
| 怎么从素材里造出素材没有的东西 (四个算子 + 配额 + 反模式) | `impl/divergence.md` |
| 发散记录的格式 | `../../assets/divergence-template.md` |
| 原子知识点本身怎么写 (五条判据 / 标题必须是答案 / 自包含 / 依据不是可选项) | `impl/rules.md` |

**发散出来的结论要带自己的依据. ** 它在素材里找不到, 所以依据写成自己的验证方式(实测: 查了哪个文件 / 跑了什么命令). 这条不破例  写不出依据的按"猜测"处理, 进边界章
