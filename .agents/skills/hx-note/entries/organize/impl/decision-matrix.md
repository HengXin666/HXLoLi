# 判定矩阵: 聚合 / 独立 / 整类整理

整理时遇到的每个"这东西该放哪", 先落进这张矩阵, 再决定要不要找人类.

## 一篇文章 (目录) 的去向

对候选文章 `A`, 问它**与当前所在分类里其它文章的关联度**:

| 关联度 | 当前分类规模 | 去向 | 谁拍板 |
|---|---|---|---|
| 强 (同主题, 读者会连着读) | 任意 | **留在原地**, 只在需要时改名/补前缀 | 档 A, 直接做 |
| 强 | 该分类自身已是一个合理分组 | **聚合进该分类**, 不新建 | 档 A, 直接做 |
| 中 (相关但不是同一主题) | 分类内已有 ≥3 篇同类 | 建议**并入某个已有分类** | 档 B, 给清单待批 |
| 弱 | 分类内已有 ≥3 篇其它内容 | **独立新建一个分类** | 档 C, 必须申请 |
| 弱 | 当前分类只有它 1~2 篇 | **整类存疑** —— 说明这个分类本身立不住 | 档 C, 必须申请 |

**关键判据是"它是不是改变了一个分类的语义", 而不是"它能不能塞进去".** 塞得进去但让分类名变得不准, 就是错的归档.

## 整类存疑的识别

出现下列任意一条, 就把该分类整体提交人类复核, 而不是只处理单篇:

- 分类里只有 1 篇文章, 且文章与该分类名不是同义反复.
- 分类里 ≥70% 的文章彼此无主题关联 (只有"都是我的笔记"这一条共性).
- 分类名与它的一篇文章目录名重复 (`005-Agent平台/001-Agent平台数据面灵活解耦`).
- 该分类里 ≥ 半数文章的关键 tag 落在别的主题下 (说明它们本来属于别处). 用 `hxloli_tags.py scan` 的 tag-篇目对应关系人工比对. **不要**用 "以该分类为上级的 tag" 作判据 —— 那要先有 `parent` 声明, 而 curated 层很可能还是空的, 会让所有分类一律命中.

## 三档自主权 (执行边界)

| 档 | 包含 | 权限 | 理由 |
|---|---|---|---|
| **A 卫生项** | 补 `NNN-` 前缀; 目录名去空格/非法字符; 删空目录; 修断链; 分配 hxid; 同步 tag 到注册表 | **直接做**, 事后报告 | 机械可验证, 可回滚 |
| **B 分类内重排** | 文章目录**语义改名** (标题含义变了); 同类文章聚合到一个已存在的分类; 一篇文章拆成多篇或合并; 删除无意义的中间层 | **列出清单待批**, 逐条给理由 | 改变阅读路径, 需要人确认语义 |
| **C 结构变更** | 新建 / 删除 / 重命名 `NNN-分类`; 跨分类迁移文章; 整类合并 | **必须人类逐条同意** | 改变知识库的信息架构 |

申请格式 (一次性提交, 不要挤牙膏):

```
申请: <动作>
现状: <当前路径与它的问题>
理由: <为什么现在的归类是错的>
建议: <改成什么>
影响: <涉及的笔记数 / 链接数 / 是否需要改 tag>
备选: <还有什么别的合理做法>
```

### A 档改名仍然会改 URL

站内**没有重定向机制**, 所以任何改名都是一次对外 URL 变更. 区别只在**语义有没有变**:

- 只修字符 (去空格、`=` 换 `-`、补前缀) -> **A 档**, 但必须把 "旧 URL -> 新 URL" 逐条列进迁移映射表, 并在报告里显式写出"这几条 URL 已变".
- 标题含义变了 -> **B 档**, 因为它同时改变了读者的预期.

不要把 "A 档 = 无副作用" 当成前提. A 档的意思是 "不需要人类先拍板", 不是 "对外无影响".

## 反模式

- **为了整齐而新建分类**: 把 1 篇文章升格成一个分类, 只是把乱推到了上一层.
- **跨分类搬文章只改目录不修链**: 链接会断, 必须同批用 `hx_docs_id.py resolve --write`.
- **先动结构再问**: 结构类改动一旦落盘, 回滚成本远高于先问一句.
- **把"整理"等同于"重命名"**: 重命名是最表层的一档, 真正的问题是归属.
