# 文风与成文结构细则

## 一、开头: 用引入, 不用摘要

反例 (摘要式): "本文将介绍 Cloudflare Turnstile 的检测机制, 包括 TLS 指纹、浏览器指纹与事件可信度三个方面."

正例 (现有笔记的实际写法):

```markdown
> [!NOTE]
> 当一个系统反复向你证明"你是机器人"时, 它到底在看什么? 是屏幕上的图片, 还是你浏览器内核里每一个不自洽的细节?
```

判据: 开头那段话, 读者**不看下文也该被勾住**. 它提出问题, 不预告目录.

## 二、正文: 图文并茂是硬要求

- 讲**机制**配结构图 (走 `archify`); 讲**对照**配表格; 讲**实现**给最小代码片段.
- 一整屏纯文字段落 = 排版事故: 拆成列表 / 加小标题 / 插图.
- 图要**服务论点**: 每张图在正文里被一句话引用 ("如上图, 检测面被切成三层").
- 需要演示页时按 `hx-docs-ppt` 出侧车 HTML, 用 `[标题 #ppt](xxx.html)` 内嵌.

## 三、结尾: 拓展升华展望

- 收束到更大的一层: 这套机制接下来会怎么演进 / 换个场景意味着什么.
- **必须区分事实与判断**: 展望段落明确标注为个人判断, 不要把猜测写成结论.
- 不写"综上所述"式复读; 也不要把局限/待办写成给读者的道歉.

## 四、标题与 tag

- 标题: 凝练且专业, 允许一个副题 (如 "深入理解Cloudflare过盾原理:无需AI从零实现CFTurnstile绕过").
- 人类改过标题后**只给建议, 不擅改**.
- tag: 先跑 `hxloli_tags.py suggest "<词>"` 查外挂注册表 `ai-docs/.hx-tags.toml`, 能复用就复用; 都不合适才新增 (见 hx-docs-layout SKILL.md 的 HXLoLiTag 一节).
- frontmatter 的 `title`/`tags` 可在 `makeDoc.py` 产物基础上修正, 但不要手写整个文件绕过模板.

## 五、读者可见 vs 仅审核可见 (铁律)

笔记的最终对象是**读者**, 不是 AI, 也不是作者的审核流程.

| 内容 | 唯一去处 |
|---|---|
| 面向读者的正文 | `index.md` |
| 生成过程、工具链、脚本命令、本地路径、验证步骤、ASR 转写、provenance | **不进正文** |
| 需要作者 review / 拍板的点、局限与待办 | `.hx-mitemite.md` (见 hx-docs-grill) |
| 引用过的外部来源 | 正文末章, 只写标题 + 链接 + 一句价值 |

成稿自检: 假装自己是第一次点开这篇文章的读者 —— 任何需要内部人才懂的操作细节、任何打断阅读的审核/待办/局限提示, 都要移出正文.

## 六、双链写法

```markdown
参见 [DSH Agent Loop 源码剖析](../003-DSH-Agent-Loop源码剖析/index.md) 讲事件循环怎么驱动每一步.
```

- 相对路径从**当前 index.md 所在目录**算起.
- 链接文字要说明那篇讲什么.
- 目录改名/移动后相对链接会失效, 改动时必须同批修链.
