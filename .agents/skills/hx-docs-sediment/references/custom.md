# 定制化沉淀 (需登录 / 特殊解析方式)

适用于登录墙后的页面、需要特定解析方式的产物 (如 GPT 对话记录)、私域文档、需要 cookie 的站点.

## 第一原则: 显式声明, 不伪装

素材来源不是公开网页时, **必须在 provenance 与对话里说清是怎么拿到的**. 不要在正式笔记里把它伪装成"公开文章引用".

## 三条可行路径 (按推荐顺序)

1. **官方导出 / API**: 优先. 例如对话记录用官方分享链接或导出文件; 笔记类应用用自己的导出. 这条最稳定、最不敏感.
2. **本机浏览器登录态**: 人类已在本机登录的前提下, 借助已有浏览器能力读取页面 (如 bridge/扩展类工具). 只用**人类已经授权**的会话, 不新建登录.
3. **人类直接提供文本**: 人类把内容贴出来或存成文件, 你只负责后续处理. 这条最省事, 也最不容易越界.

**禁止**: 自动登录、替人类输入密码、绕验证码、伪造身份. 需要凭据时停下来问人类.

## 以 GPT 对话沉淀为例

1. **拿到对话**: 优先官方分享页 / 导出文件; 拿不到再让人工提供 `markdown` 或文本.
2. **保留角色结构**: 沉淀时区分"人类提出的问题/约束"与"模型给出的回答", 不要把两者混成一段叙述.
3. **模型输出不等于事实**: 模型可能自信地编造 API、版本号、数字. 凡是可验证的论断**必须外部复核**, 核不了就标 `[不确定]` 或删掉.
4. **提炼的是可复用结论**: 对话里的探索过程很有价值 (试错、被否决的方案), 但要重写成"问题 → 候选方案 → 为什么选它".
5. **脱敏**: 去掉 token、账号、内网地址、私人信息; 截图同样要打码.

## provenance 记录格式

在对话中 (不写进正文) 给出:

```text
来源类型: 登录态页面 / 官方导出 / 人类提供文本
获取方式: <具体工具与命令, 或 "由人类粘贴">
获取时间: <日期>
可信度备注: <是否有截断、是否只拿到部分对话、模型输出是否已复核>
```

正文末章仍按常规列引用: 若来源不可公开访问, 写清"来源为私有对话记录, 不可公开引用", 不要伪造一个可点开的链接.
