# 公开文章 / 网页沉淀

## 链路

1. **抓正文**: 用 `argo_fetch` (HTTP 优先, 遇 Cloudflare/JS 渲染自动升级; 可用 focus / mode=extract 只取正文与结构化字段). 抓不到时再考虑 `web_search` 找镜像或译文.
2. **记元数据**: 标题、作者、发布时间、原始 URL —— 这些要进正文的"资料来源"与末章引用.
3. **重述而非摘抄**: 文章的价值往往在**论证链**而不在结论. 用自己的话说清: 它要解决什么问题 → 主张是什么 → 依据是什么 → 边界在哪.
4. **交叉复核**: 文中关键论断若与你已知事实冲突, 先查证再决定怎么写; 不要因为"原文这么写"就照搬.
5. 回到固定契约: 模板初始化 → 成文 → 标点检查 → sidebar 注册.

## 引用规范

- 正文里第一次提到原文时给出**行内链接**; 末章集中列出来源 (标题 + 链接 + 一句出处价值).
- 直接引用要**短引** (`>` 引用块 + 出处); 不要大段搬运原文.
- 译文类文章要注明"原文 + 译者", 不要把翻译稿当原始来源.

## 判断"值不值得沉淀"

先问三个问题, 答不上来就别写:

1. 这篇讲的东西, 半年后还成立吗? (纯时效性新闻 → 不沉淀)
2. 我的笔记比"存个书签"多提供了什么? (必须有: 提炼、验证、与已有笔记的连接)
3. 与 `ai-docs/` 已有笔记是否重复? (重复 → 合并或只做增量补充)

## 常见坑

- **只抄结论**: 原文的结论脱离它的前提就是错的, 必须连前提一起写.
- **丢出处**: 抓下来的正文里往往带大量导航/推荐噪声, 提炼时容易漏掉真正的署名与发布时间.
- **时效**: 工具用法、版本号、API 名称会过期, 写的时候标注"截至 <时间>".
- 页面需要登录或特殊解析 → 转 [custom.md](custom.md).
