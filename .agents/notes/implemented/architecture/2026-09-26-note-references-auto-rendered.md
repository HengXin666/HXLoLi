# Agent Note: 引用关系方框改为全站注入, 站外来源按「域名@标题」显示

Status: implemented

Decision-ID: note-references-auto-rendered

- **引入于**: `f28d9cfd13` (原实现) / 本次改动见下方影响清单
- 取代: 本篇原先即承担 `2026-09-26-note-references-auto-rendered` 的决策, 现就地更新为线上现实 (自动渲染这个决定没有被推翻, 被推翻的是它的数据面与呈现面)

## Code

- `docusaurus.config.ts`
- `plugins/note-references-plugin.mjs`
- `src/components/NoteReferences/index.tsx`

## Problem

原实现把三件事压在了一个页签里, 上线后暴露三个问题:

1. **数字与内容对不上.** 页签写「本文引用 (0)」, 底下却列着 9 条站外来源  计数只数站内出边, 而面板画的是站内出边加站外来源。读者看到的是自相矛盾, 只能判断功能坏了。
2. **站外链接显示整条 URL.** 一条带 commit hash 的 GitHub 链接有 90 字符, 列八条就把方框撑满; 而真正有信息量的部分 (哪个域名、那篇叫什么) 全被路径噪声埋掉。
3. **只有 ai-docs 有方框, 且没有引用时整个消失.** 方框的缺席意味着两件事: "插件没跑"和"这篇恰好没引用"。读者分不出哪个。
4. **数据只覆盖 `ai-docs/`.** `docs/` (935 篇) 与 `blog/` (42 篇) 的引用关系完全没有承载物。

## Decision

**站内外分成三个平级页签, 数字各数自己那一栏; 站外来源显示 `域名@标题`; 三个内容区都注入, 且在页面存在时恒常显示。**

- 数据面从「ai-docs 专用」扩到三个内容区, 且**只在同区建边**  Docusaurus 按插件解析 markdown 链接, 跨区相对路径不会被 resolve, 记下来就是死链。
- slug 权威表问 Docusaurus 要 (`allContentLoaded` 里读 `allContent`), 不再自己复刻 `computeSlug`。规则含数字前缀剥离、index 归一、frontmatter slug 覆盖, 复刻必然漂移  而仓库里已经有这个函数的两份副本, 再加一份就是第三个会跑偏的真相源。
- 载荷**由 remark 注入成组件 props**, 不再落盘成组件 import 的 `data/*.ts`。原因见下一条。
- 站外锚文本用 `域名@标题`, 完整 URL 挪进 `title` 属性 (链接本身不变, 悬停仍可见全部信息)。
- 私有内容不进方框: 符号链接、`_` 开头路径段、`hx_protected` 三条同时判。只判一条会在别的机器上漏  符号链接只存在于本地开发。

## Alternatives considered

- **保留单页签, 只把站外数字加进「本文引用」的计数.** 最强理由: 改动最小, 不动数据结构, 一行就够。否决: 那是把"站内延伸阅读"和"结论出处"两种东西混成一个数字; 数字对了, 分类仍然是错的, 而下一次改文案还会再错一次。
- **站外来源作为「本文引用」面板内部的一个分组标题 (原实现的形态).** 最强理由: 视觉上更紧凑, 不必让读者多点一次。否决: 实测这正是那个"数字 0 底下挂 9 条"的现场  分组标题里的小数字和页签的大数字并存, 读者要先分辨"哪个数字才对"。三个平级页签让每栏只有一个数字。
- **让组件 import 一份全站表 (原实现的形态).** 最强理由: 实现最简单, remark 完全不用碰, 数据在构建期就全部算好。否决: 边表是全站的, 实测 1000+ 篇共约 364KB (gzip 约 107KB)。组件 import 会让它进全站共享 chunk, 每一篇页面都替**所有**页面付这份钱; 而单篇平均只用到约 367 字节。注入 props 后数据随该页自己的 MDX chunk 走, 别的页面一字节都不付。
- **把全站表拆成按内容区分片, 组件按路由取.** 最强理由: 兼顾"不 import 全站"与"组件自取数据"。否决: 仍要一次运行期 fetch 或一份额外产物, 而 remark 注入在构建期就把成本压到零; 且分片后 `docs` 那片仍有 360KB。
- **让 remark 插件自己扫内容目录.** 最强理由: 少一次构建期落盘, 少一个中间产物, 数据流更直。否决: md 的编译可能发生在 webpack 的 worker 里, 那样每个编译单元都会重读上千个文件 (935 篇 × 1010 次读取)。把扫描钉在 `allContentLoaded` 这一次, remark 退化成一次文件读取加一次查表。
- **没有引用时整个不渲染方框 (原行为).** 最强理由: 页面更干净, 不留空框。否决: 这让"方框缺席"同时意味着"插件没跑"和"这篇没引用"; 而用户明确要求常驻  想看的是"这篇确实没有引用", 那是个事实, 不是空白。
- **站外来源显示完整 URL (原行为).** 最强理由: 一眼知道会去哪, 不用悬停。否决: 域名已经在锚文本里了, 而标题比路径后半段有信息量得多; 完整 URL 放进 `title` 后两种信息都还在。
- **用 `docs-links-graph` 复用全站图.** 理由: 已有 `generate-docs-graph.mjs` 与 871KB 产物。否决: 它扫 `docs/` 不含 `ai-docs/` 与 `blog/`, 且它是**独立图页面**的输入, 不区分同区/跨区, 会把 404 的跨区边也写进去。

## Consequences

- 三个内容区都恒常渲染引用框, 没有引用时显示空态而不是消失。
- 站外来源一栏在任何页面都只列站外, 数字与内容一一对应。
- 单页载荷平均约 367 字节, 随该页 MDX chunk 走; 全站不再共享一份 364KB 的边表。
- 私有内容 (私密笔记、persona、加密占位) 不进公开的引用框, 三条判据同时生效。
- 代价: 引用图在构建期才算, 新写的链接要重新构建 (或在开发服务器上等一次重扫) 才出现在方框里。
- 代价: 载荷落盘 `data/noteReferences.json`, 属于构建产物; 它不进版本库, 每次构建重建。
- 踩过的坑 (原实现留下的, 仍然适用): 站内链接前缀不能写死 `/knowledge-base/...`  本站双平台部署, baseUrl 在 GitHub Pages 是 `/HXLoLi`、Cloudflare 是 `/`, 写死会在其中一边 404, 必须经 `withBaseUrl`。
- 踩过的坑 (本次新增): 博客列表页用 `file.md?truncated=true` 编译**同一文件**的截断产物, 不挡住它, 引用框会出现在列表里每条摘要下面。判据用「原文有截断标记而当前编译内容里没有」。
- 踩过的坑 (本次新增): remark 阶段拿不到 permalink  它要到更晚才随 metadata 生成。所以载荷的键是**源文件相对路径**, permalink 放在值里。
