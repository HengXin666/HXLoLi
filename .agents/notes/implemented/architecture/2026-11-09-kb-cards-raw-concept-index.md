# Agent Note: 知识库改为卡片 + 原件 + 概念索引, 写多错多交给机械规则

Status: implemented

Decision-ID: kb-cards-raw-concept-index

- **引用落点**: `scripts/kb/kb.py` 的 `main`
- 方案全文: `.hark/plan.md` (v3, 2026-11-09). 证据: `ai-docs/.hx-staging/hx-note-trial-20261108/README.md`

## Code

- `scripts/kb/kb.py`

## Problem

现有链路是 素材 -> `.hx-info.md` 事实源 -> AI 改写成 `index.md` -> 可视化侧车. 2026-11-08 对照试跑里, 同一份事实源改写出的 6 篇稿子保真盲审全部 FAIL: 每篇遗漏 8 到约 55 条, 新增 2 到 9 条事实源里没有的论断, 歪曲 1 到 4 条. 读者在成对评审里点名有用的几乎全是参考件 (表, 检查表, 实测数, 命令, 骨架代码), 点名该删的几乎全是引入, 升华, 展望段.

使用者原话 (2026-11-09): 「写太多了, 我不想看. 看一次就永远不会再看第二次」; 「定位是和我认知同步的知识库」; 关于「最近和启发」: 「用户如果都不知道, 为什么要求 ai 知道? 写多错多」.

另外两个结构问题: 原始素材在 `ai-docs/.hx-staging/` 下被 `*` 整体 gitignore, 不进版本库; `.hx-info.md` 只在 16/45 篇存在, 仓库里没有任何代码读取它.

## Decision

- 不再产出 AI 改写稿. 知识的发布单位是**卡**: 一句结论 + 原件逐字摘录 + 一个可执行动作 (检查项 / 命令 / 要作者回答的问题), 正文 ≤ 15 行. 卡类型只许 cmd, check, decide, measure, pitfall, question 六种, 判据是「看第二遍还有没有用」
- 原件放 `kb/raw/` 进 git, 只读. 作者自己的记录放 `kb/raw/self/`
- 卡按概念索引, 概念表 `kb/concepts.yaml` 由作者维护, 不按篇组织
- 「写多错多」写成 `scripts/kb/kb.py lint` 的机械规则: 一卡一句 (C3), 摘录必须是原件逐字子串 (C4), 结论里的数字必须在原件里找到 (C5), 禁用句式 (C7), 结论里的专名与引文 (反引号, 点号路径, 标识符, 引号内原文) 必须在原件里找到 (C9), 结论里超过 40% 的汉字二元组摘录里没有即视为改写 (C10), 自指内容的依据必须全部来自 `raw/self/` (M1), A 档方案卡在作者回答定位问题前只能产出 question 卡 (P1). 全部是正则, 子串和路径判断, 不用 AI 评审
- `kb.py` 放在独立子目录 `scripts/kb/`, 不和 `scripts/` 下其他决策的代表文件同目录, 避免兄弟代码互相触发配对

## Alternatives considered

- **什么都不做, 继续修改写链路的闸门.** 最强理由: hx-note 已有 139 个文件的流程和 lint, 投入很大, 11-08 的写前清单方案刚落地还没验证. 否决: 6/6 保真失败出在改写这一步本身; 压短后每句更容易讲过头 (11-01 T1/T2 分别要 2 轮, 3 轮保真才过). 外部评测 FaithBench (NAACL 2025) 里主流幻觉检测器在难例上约 50% 准确率, 用 AI 盲审兜底改写不可靠
- **复用现有 `.hx-info.md` 作为发布物, 不建卡.** 最强理由: 事实源已带依据, 不用新格式. 否决: 它按篇组织, 一篇几百行, 仍是「读」的形态而不是「用」的形态; 没有动作字段, 没有概念索引, 只覆盖 16/45 篇
- **保留叙事文章, 只降语气规则.** 最强理由: 成对评审里 OLD 稿结构分三个主题都更高. 否决作为默认产出: 使用者明确不想读长文, 且叙事段正是新增论断的主要来源. 作者自己想写的长文不受此决策约束

## Consequences

- 新增 `kb/` 目录与 `scripts/kb/kb.py`. 现有 hx-note / hx-ai-docs 流程和 45 篇存量暂不改, 等 kb 跑通再定
- 已知缺口: 迁入的三个试跑主题只有 `material.md` 摘录, 网页原文当时没有落盘, 卡的逐字依据最多追到摘录层. 记在 `kb/README.md`
- 2026-11-09 用 B 稿切卡试验 (292 张, 结果在 `ai-docs/.hx-staging/kb-lint-trial-20261109/README.md`, 不进 git): 盲审 29 条里, 第一版规则实质拦住 11 条; 加 C9 C10 后 25 条, 只被 C3 拦 2 条, 漏 2 条 (分类错误, 「原件没说」类断言). 代价是 B 稿 74% 的行过不了 C9/C10, 这是有意的: 卡的结论只能贴着摘录写
- C5 只认阿拉伯数字, 「大半」「多数」这类定性词和中文数字拦不住; C3 的字数按汉字和英文词各算 1
- M2 (raw/self 只能作者写) 和 U1 (90 天 0 调用进删除候选) 还没实现
