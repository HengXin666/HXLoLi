## Problem

沉淀流程产出的笔记在**内容上没有增量**: 读一份素材, 得到的是那份素材的复述。
具体形态是"把素材的句子换一种说法, 再补几句评价"。这不是模型能力不足 
实测在 `OpenVetta` 那份素材上, 素材明明包含 4 条以上可以推导的新结论, 而写出来的
`.hx-info.md` 全部是素材原句的改写。

原因有两条, 都可复现:

1. **没有被要求发散。** 流水线的每一步都在约束"不要写什么" (不许铺垫、不许反问、
   不许人称、不许配图), 但**没有任何一步要求"产出素材里没有的东西"**。
   模型在只被约束的环境里的最优策略就是忠实复述  复述永远不会违规。
2. **"请发挥创造力"这类指令无效。** 面对空白的"还能想到什么", 模型产出的是感想
   (「这套设计体现了对细节的极致追求」), 而感想不可验证、不可反驳, 等于噪声。
   要求 (requirement) 与算子 (operator) 的区别就在这里: 前者只说"要发散",
   后者说"把这条规则抽成它所属的类, 再看素材里还有谁在遵守同一条规律"。

## Decision

### 一、发散做成四个可执行算子, 不是一句要求

`steps/3-atom/impl/divergence.md` 给出四个算子, 每个都说明"做什么 / 判据 / 例子":

| 算子 | 做什么 | 判据 |
|---|---|---|
| 换轴 | 把具体规则抽成它所属的类, 再找同类 | 同一规律在素材里**至少出现两次**才算抽对 |
| 跨源并联 | 两条看不出关系的规则, 能否被同一原理解释 | 原理必须能**反推回**两条原始规则 |
| 迁移 | 搬到自己的另一个项目 | 必须给出**可执行的检查动作** |
| 拆代价 | 这条取舍放弃了什么, 谁在什么时候付款 | 付款人必须具体到某类任务 |

配额是硬的: 每个算子至少试一次, 至少 4 条标 `[素材没有]` 的产出, 每一条都要带判据。

### 二、闸门在 `done atom`, 不在 doctor

`hx_flow.py` 的 `done` 在推进阶段 3 时检查 `source/divergence.md`:
文件缺失或带判据产出少于 4 条时**直接拒绝推进**。doctor 里只留一条"仅报告不拦截"。

为什么放 `done` 而不是 doctor: doctor 是交付前最后一道, 到那时正文已经派生完成,
发现没发散要推倒重来; 而这个闸门的意义正是在**写正文之前**拦住复述。

判据是机械的, 且**逐格判而不是拼接后判**: 产出行必须至少有一格"判据/去向"是真的
非占位内容 (含可查动作的字词), 排除纯感想词与 `<...>` / `...` 占位符。
这条实测踩过: 最初把两格拼接后再判, `<...>` 与 `...` 合成 `<...> ...` 后不再是纯占位符,
于是 2 条合格 + 2 条占位的记录被判成 3 条。

### 三、发散产出的依据是"自己的验证", 不破依据必填这条铁律

发散的结论在素材里找不到, 所以依据不可能是"素材第 N 节"。规则改为: 依据写成**自己的
验证方式** (实测: 查了哪个文件 / 跑了什么命令)。给不出判据的按"猜测"处理, 进 `[不确定]`
与边界章, 不许当结论写进正文。

这样保真盲审 (阶段 8) 不需要改: 只要结论进了 `.hx-info.md` 并带依据, 它就是合法事实源;
只写进正文而没进事实源的仍然会被拦。

## Alternatives considered

- **什么都不做, 在 `.hx-info.md` 的规范里加一句"要写出自己的理解"** — 最强理由: 零成本,
  且现有规范已经很长, 再加一条的边际收益看起来很低。否决: 这正是病因 
  要求与算子是两类东西。"写出自己的理解"面对空白只会产出感想, 而感想不可验证,
  会直接污染知识库。算子把发散从灵感问题变成执行问题, 每个算子做什么是确定的。
- **让模型自由发散, 不加配额与算子** — 理由: 算子会限制它, 自由发挥或许能撞到更好的东西。
  否决: 实测自由发挥的产出 100% 是感想与万能结论 (「任何规范都要保持一致性」),
  因为模型面对完全开放的空间只会选最安全的表述。**结构不是限制, 是让它敢下判断的前提**。
- **把闸门放进 doctor 而不动 done** — 理由: done 是简单状态推进, 往里塞质量检查会让
  状态机承担它不该承担的职责。否决: 位置错了。这个检查的价值在于**写正文之前**生效;
  放进 doctor 等于事后追认, 而事后改内容的代价远大于事前 (已有实证: 保真盲审发现
  正文偏离时要回写事实源再重派生)。
- **用 sub-agent 做发散, 主流程只收结果** — 理由: 换一个上下文可能更容易跳出复述惯性;
  且与步骤 7/8 的盲审机制一致。否决(本次): 发散需要**素材全文 + 自己的项目上下文**
  (算子三"迁移"的判据要靠本仓文件), 而盲审的污染控制铁律要求不给这些。两者要求相反,
  硬凑会把两个机制都做坏。若以后实测主流程发散质量仍差, 这是第一个该重试的方向。

## Consequences

- 复述稿在关键路径上被拦住, 且拦住的位置在写正文之前。
- 代价一: 纯资讯类素材 (事件、观点) 没有可发散结构, 需要 `--force` 才能推进。
  这是刻意的摩擦  默认必须发散, 跳过要留痕。
- 代价二: 判据格是**文本启发式** (查有没有"查/跑/测"这类动作词), 可以被绕过 
  写"查一下"就能过。它是下限而不是防线。真正的质量仍靠人的审核 (阶段 4) 与
  保真盲审 (阶段 8) 兜住。这是刻意的取舍: 宁可漏报 (由后续步骤兜) 也不误报
  (误报会训练执行者不信闸门)。
- 规则的行为边界: 闸门只看 `source/divergence.md` 的格式与条数, **不判断发散质量**。
  一份 4 条全错的记录照样能过  但它进了事实源之后会被保真盲审与人类审核看到,
  比原来"连记录都没有"要可追责得多。
- 未做: 没有把发散算子推广到其他素材类型 (`research` / `local`)。理由: 那两类素材
  本身就是"你已经知道要什么才去找"的形态, 发散收益未经实测。先在一类上跑出数据。

闸门"真的会拦"的实证 (三条路径全部实跑):

```
done atom, 缺 source/divergence.md        -> error: 产物缺失, 拒绝推进
done atom, 记录里只有 2 条带判据的产出    -> error: 只有 2 条, 要求 >= 4
done atom, 4 条带判据                     -> done: 3 atom
```

判据格的判力实测 (4 组 fixture):

```
全感想 (用心/极致/值得/一致 + <...>/...)  -> 0 条
3 条真判据 + 1 条 <...> 占位             -> 3 条
4 条真判据                               -> 4 条
```

算子有效性: 在 `OpenVetta` 素材 (`.hx-info.md` 454 行) 上手工跑过五个算子, 产出
"连续量必须离散成有名字的桶" (换轴, 由透明档位 + 间距三档 + 圆角四档三条独立证据支撑)、
"1px 是因为边框升格为唯一层级载体" (跨源并联, 能反推回两条原规则)、
"分段等亮度规则不适用于有真实大小关系的图" (反转) 等结论  这些在素材原文里都不存在。
