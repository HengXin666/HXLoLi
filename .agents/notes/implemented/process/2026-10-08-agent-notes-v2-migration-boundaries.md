# Agent Note: v2 迁移保留真实源码与精确保护范围

Status: implemented

Decision-ID: agent-notes-v2-migration-boundaries

## Problem

旧仓库包含根目录源码, 类型声明, 常量配置和模块导出. 只允许受保护目录与函数锚点时, 这些真实代码无法完整接入双链, 要么丢失原有保护范围, 要么增加仅用于通过校验的占位函数. 修改配置到 v2 后, 旧提交的 v1 配置也不能作为普通 v2 配置读取

## Code

- `.agents/skills/hx-agent-notes/scripts/redline/snapshot.py`
- `.agents/skills/hx-agent-notes/scripts/setup/install.py`

## Decision

既有保护范围中的 shell, JSON, YAML 与文档等非 AST 资源继续参与 diff, 改动时报告 resource-review 并定位对应文件. 这类诊断要求人工核对决策及引用, 不声称 parser 已证明其双链. active note 的 Code 仍只列受支持的真实源码声明

比较基线按 v1 原有 glob 语义展开, 单星号不跨目录, globstar 可跨目录. note 的 Markdown 示例和行内代码不是实际文档链接, 真正的正文链接仍严格核对. 生成入口允许添加决策注释后幂等安装, 可执行 AST 改动仍拒绝覆盖

guarded 使用精确仓库路径, 允许目录或单个现存源码文件, 不使用 glob 或根目录占位符. Code 仍每个直接父目录只列一个代表文件, 与对应 AST 锚点双向核对

函数使用原有合法锚点. 纯声明代码将多行注释绑定到 Tree-sitter 识别的真实导出, 变量, 类型或接口声明, Python 模块配置可使用紧邻赋值的连续注释. 类头, 普通字符串, 隔空的文件头和注释仍不算锚点, 不新增空函数或改变业务职责来通过校验

仅在同一 diff 显式将配置从已识别的 v1 结构改成 v2 时, 比较端把旧 guarded 模式展开为旧提交中的精确源码路径并保留到扫描并集, 同时报告 migration-review 和 policy-review. 运行目标仍只接受 v2, 不将 v1 仓库自动判为 v2 有效

每个仓库版本化自己的技能实现, 使用同一严格入口与容错 GitHub 工作流. 决策统一维护在 `.agents/notes`, 没有本仓有效代码约束的旧记录直接退役, 有指导价值的理由先迁入存活决策, 并清理入站引用. 历史由 Git 保留, 冻结的已有归档保持原样

## Alternatives considered

- 什么都不做 / 复用现有: 不扩大 AST 节点集合且没有迁移工作, 但根目录源码和声明目录无法建立真实双链
- 只保护已有函数的目录: 容易通过原有门禁, 但会使类型和配置在迁移中失去原有保护
- 增加空函数或包装无关业务函数: 能满足函数形状, 但制造虚假锚点, 无法让读者找到真正受约束的位置
- 忽略 v1 比较基线: 首次迁移校验容易运行, 但会掩盖旧保护范围被删除的事实, 因此保留旧路径并报告 review
- 允许任意文件头注释: 文档接入更方便, 但不能证明注释绑定到真实代码, 因此继续使用 AST 归属和紧邻位置判据
- 单独保留参考记录目录: 可以容纳没有源码落点的旧记录, 但会把决策拆成两套目录并增加维护负担, 因此使用同一 notes 树和 Git 历史

## Consequences

源码的业务行为与公开契约保持稳定, 双链能覆盖真实声明和根目录源码. 首次迁移的 diff 明确需要独立 review, 全图结构可以用完整 v2 快照校验. AST 只证明节点和关系, 不证明决策理由是否真实
