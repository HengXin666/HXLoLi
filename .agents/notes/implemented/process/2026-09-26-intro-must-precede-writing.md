# Agent Note: 引入必须来自动笔前已发生的遭遇, 不许为主题回找

Status: implemented

- **引入于**: `f28d9cfd13`
- **引用落点**: 无源码引用 (约束的是写作流程的**引入取材时机**, 落在 templates/ 与 steps/ 的 markdown 契约里; 判据本身是判断题, 无法落到某个代码声明)
- 影响: `templates/interest-outlook.md` 的引入一节; `steps/1-intake/index.md` 新增「引入的素材」环节与过关条件; `steps/6-derive/index.md` 的输入清单从两样变三样

## Problem

这篇笔记的第一版引入, 写的是「我为什么要做这件事」那一类 —— 交代动机, 落点真实。

**它的形式指标全部合格**: 第一人称有、落到作者自己的笔记上、没有套话、句长 26 字也在
实测算出的线内。lint 零命中, 两道盲审也都过了。

但作者读完之后说「感觉还是有点奇怪, 我无法表述出来」。

> **补充 (2026-09-26 同日)**: 上面这段引文已从笔记里改掉, 换成「你这 ai 味道也太重了吧
> 谁他妈会写这种句子」——因为后面这句才是**先于写作发生**的。原引文本身只在这次改动前
> 存在过, 未进版本库, 所以这里不再逐字引它, 改述其形状。反例的价值在形状 (交代动机 ->
> 形式全过 -> 读者仍觉隔一层), 不在那几句原话。

## Decision

把「那件事在动笔之前就发生过吗」立成引入的**唯一硬判据**, 写进三处:

| 位置 | 作用 |
|---|---|
 `templates/interest-outlook.md` 的引入一节 | 写的时候判 |
| `steps/1-intake/index.md` | **选题时就问**, 把遭遇原文记进 `intake.md` |
| `steps/6-derive/index.md` | 输入清单从「画像 + 语料」变三样, 明确「引入不许在这里现编」 |

差别不在形式上, 在**因果方向**:

```
作者的引入: 遇到事 -> 有情绪 -> 写下来        (情绪是输入)
倒推的引入: 决定写文 -> 找个合适的情绪 -> 写  (情绪是装饰)
```

实测依据 (40 篇作者手写引入 vs 那一版): 感叹/欢呼 29 次对 0、具体时间地点 19 次对 0、
情绪词 14 次对 0。作者的引入都钉在一个具体时刻或一次具体遭遇上, 因为那些文章是**先有遭遇**。

推论: **选题顺序要反过来** —— 从已经积累的遭遇里挑着写, 不要先定主题再回找入口。

## Alternatives considered

- **什么都不做, 只靠现有的两条盲审** — 最强理由: AI 味盲审 + 保真盲审已经能抓不少问题,
  而且加新规则会让流程更重。否决: 这一版正是两道盲审都过了、形式指标全过的样本 ——
  盲审看的是「这段话说得对不对」, 它看不到「这件事有没有真的发生过」, 因为后者不在文本里。
- **把它做成 lint 规则** — 理由: 能机械查的才靠得住, 这是本仓库一贯的做法。否决:
  这件事**没有文本特征**。上一版的字面特征 (人称、句长、无套话) 与合格引入完全一样,
  差别在文本之外。硬做成规则只会误伤 —— 与「AI 味检测不要当硬门禁」是同一个道理。
- **只在模板里写一句提醒** — 理由: 改一处最省, 而且写引入时确实会读到模板。否决:
  写引入时木已成舟 —— 那时手上只有一份整理好的知识, 除了往回找没有别的办法。
  必须提前到步骤 1: 问人类一句「你是什么时候碰上这件事的」, 拿到原始遭遇。

## Consequences

- 流程多了一问 (步骤 1), 但换来的是引入的**来路**可用。
- 用户没有相关遭遇时的退路写清楚了: 退成「我为什么要整理这个」的真实动机;
  连动机都没有就在答题卡写明, **不许编**。
- 代价: 这条判据没法自动检查, 只能在步骤 1 与步骤 6 靠自问。已在两处都写明是判断题。
