# 番剧库设计说明 (/anime 与 /anime/details)

日期: 2026-11-01. 决策记录见 `.agents/notes/implemented/feature/2026-11-01-anime-page-refactor.md`. 同目录 `anime-page-redesign.md` 是同日另一份待确认方案 (接 HX-UI 令牌), 本文是已实施版本; 两者的差异见第 7 节.

## 1. 信息架构

```
/anime
├─ 标题行: 追番记录 · 番剧关系图 →
├─ 体量: 共 160 部 · 在看 13 · 看过 134 · 想看 2 · 搁置 10 · 抛弃 1
├─ 工具栏 (sticky)
│   ├─ 搜索 (中文名 / 原名 / 短评, 按 / 聚焦, Esc 清空)
│   ├─ 观看状态 chips (多选, 带分面计数)
│   ├─ [标签与更多 (n)] -> <dialog>: 标签分组多选 + 全部 / 任一命中 + 首播年份 + 评分下限
│   ├─ 排序: 最近更新 / 首播日期 / 评分 / 名称
│   └─ 视图: 海报 / 列表
├─ 生效条件行: N / 160 部 · [看过 ×] [#萝莉 ×] 且 [#日常 ×] · 清空全部
└─ 结果
    ├─ 首播日期: 按番剧季度分组 "2026 秋 · 10 月番"
    ├─ 最近更新: 按年月分组 "2026 年 9 月更新"
    └─ 评分 / 名称: 不分组
```

默认: 全部状态、按最近更新. 160 部里在看只有 13 部, 默认只显示在看会让人以为库就这么点.

## 2. 筛选模型

| 维度 | URL 参数 | 多选 | 维度内语义 | 默认 |
| --- | --- | --- | --- | --- |
| 搜索 | `q` | - | 子串, 不分大小写 | 空 |
| 观看状态 | `status=watching,watched,wish,onhold,dropped` | 是 | 或 | 全部 |
| 标签 | `tag=萝莉,日常` | 是 | `match=all` 且 (默认) / `match=any` 或 | 无 |
| 首播年份 | `year=2024` | 否 | - | 不限 |
| 评分下限 | `score=8` | 否 | ≥ | 不限 |
| 排序 | `sort=update / air / score / name` | 否 | - | update |

- 维度之间一律"且". 默认值不写进 URL, `/anime` 就是默认视图.
- 旧链接 `/anime?tag=萝莉` 原样可用 (首页番剧块与详情页都在用).
- 标签默认"全部命中", 因为这个库的主要用法是收窄: 萝莉 且 日常 = 13 部; 任一命中选这两个就有 52 部, 多选失去意义. 选两个及以上标签时面板里出现切换, 并用一句话写明 ("同时带有「萝莉」和「日常」的番"); 生效条件行里标签之间写出"且"或"或".
- 分面计数: 每个选项旁的数字 = 其他维度条件不变时选上它会剩几部, 为 0 且未选中的置灰不可点.
- 历史: 点选类改动 push (后退撤回一步), 搜索防抖 200ms 后 replace (不刷历史).
- 只有视图密度存 localStorage.

回答原来的三个问题: 现在能多选标签 (不限个数); 能组合 (状态多选 × 标签多选 × 年份 × 评分 × 搜索); URL 能分享出完整筛选状态 (含排序).

### 3.3 标签的展示形态

一排平铺按钮换成:
- 筛选面板里按组分栏的多选 chips, 带计数, 悬停显示口径, 选中的本站分类在下方列出口径;
- 卡片上的 `#标签` 按钮, 点了直接加进或移出筛选 (已选的高亮).

首页番剧块不变 (前 10 个标签, 萝莉高亮), 链接格式兼容.

## 4. 展示

- **海报** (默认): 2:3 封面, 桌面按 `minmax(168px, 1fr)` 自动排 5 到 6 列, 手机固定 2 列. 封面左上状态角标 (在看粉 / 看过绿 / 想看蓝 / 搁置黄 / 抛弃灰), 右上评分, 底边进度条 (`watched_eps / eps`, 看过 = 满). 悬停或键盘聚焦时封面压暗并浮出短评. 下面是标题 (两行截断)、进度文字、年份、最多 3 个标签.
- **列表**: 64px 小封面 + 名称 / 状态 / 评分一行, 原名 / 年份 / 进度一行, 进度条, 两行短评, 全部标签. 适合按名字找或看短评.
- 卡片不是一个大链接: 封面与标题链到详情, 标签是独立 button, 不在链接里套按钮.
- 去掉两侧猫娘与 `#2b2b2b` 圆角盒, 内容区最宽 1240px.

## 5. 加载 / 错误 / 空态

| 场景 | 旧 | 新 |
| --- | --- | --- |
| 番剧库加载中 | 一张假的"未知番剧"占位卡 | 12 个骨架 tile (shimmer, `aria-busy`) |
| CDN 失败 | 永远停在加载 | 错误说明 + 重试 (store 失败后清掉在途 promise, 重试会真的重新请求) |
| 筛空 | 一行"这个状态下没有…" | "没有同时满足这些条件的番" + 最多 3 个"去掉 X, 有 N 部"一键撤销 + 清空全部 |
| 详情页冷启动 | 先闪 404 + 御坂图 | SSR 与水合首帧只出骨架; 加载中骨架; 失败出重试; 数据到了确实没有才 404 |

详情页 404 的两个来源: (1) Docusaurus 静态生成的 HTML 没有查询串, `id` 为空, 旧代码直接渲染 404, 浏览器先显示这份 HTML; (2) 水合后 12 MB 的 JSON 还没到, `records` 为空, find 不到也是 404. 现在两处都按状态分流. 注意: 详情页路由是 `/anime/details?id=<id>`, 不是 `/anime/details/<id>`.

## 6. 凭什么算"更现代"

不是换皮. 下面每条都是可验证的交互性质, 旧页面都不满足:

1. **URL 即状态**: 任何筛选组合都是一个可复制的链接, 刷新与分享都能还原; 后退键撤回上一步筛选. 验证: 选"看过 + 萝莉 + 日常 + 按首播", 复制地址到无痕窗口, 结果一致.
2. **分面筛选带即时计数**: 选之前就知道会剩几部, 不会点出空结果. 验证: 选萝莉后, "校园"旁的数字等于 萝莉 且 校园 的部数.
3. **生效条件可见、可逐个撤销**: 不用回忆自己点过什么. 验证: 生效条件行与 URL 参数一一对应, 点 × 只去掉那一个.
4. **组合语义写在界面上**: 多选标签明确写"全部命中 / 任一命中", 条件之间显示"且 / 或".
5. **内容优先、密度可选**: 第一屏就是十几张封面, 不是两排页签加一张宽卡; 要读短评切列表.
6. **三态反馈**: 加载 (骨架)、错误 (可重试)、空 (给出路) 都有明确界面, 不出现假数据和假 404.
7. **移动优先**: 窄屏状态 chips 横向滑动, 标签面板变底部抽屉 (原生 `<dialog>`), 网格 2 列.
8. **键盘与读屏**: `/` 聚焦搜索, Esc 关闭面板 / 清空搜索; chips 用 `aria-pressed`, 视图与组合方式用 `role=radio`, 结果数 `aria-live`; 尊重 `prefers-reduced-motion`.
9. **零新依赖的性能**: `content-visibility: auto` 跳过屏外卡片的布局与绘制; `getRecordTags` 按记录缓存; 筛选与计数全在 `useMemo` 里.

## 7. 与 anime-page-redesign.md 的差异

那份方案主张接 HX-UI 令牌作用域 (新增 `src/css/hx-ui-scope.css`, 改 `docusaurus.config.ts`, CSS module 只用 `var(--token)`) 并用 UI 门禁脚本检查. 本轮没做: 它要新增全局 CSS 与改站点配置, 超出本轮范围, 那份方案也标着待确认. 本轮样式只用 Infima 变量与半透明白, 结构与 class 名独立于颜色, 以后接令牌只换 CSS module 里的色值.
