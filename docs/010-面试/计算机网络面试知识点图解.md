## 二、TCP 三次握手与四次挥手

```mermaid
sequenceDiagram
    participant C as 客户端
    participant S as 服务端

    rect rgb(200, 235, 255)
    Note over C, S: 🤝 三次握手（建立连接）
    C->>S: ① SYN=1, seq=x<br/>(客户端 → SYN_SENT)
    S->>C: ② SYN=1, ACK=1, seq=y, ack=x+1<br/>(服务端 → SYN_RCVD)
    C->>S: ③ ACK=1, seq=x+1, ack=y+1<br/>(双方 → ESTABLISHED)
    end

    Note over C, S: 📡 数据传输中...

    rect rgb(255, 230, 230)
    Note over C, S: 👋 四次挥手（断开连接）
    C->>S: ① FIN=1, seq=u<br/>(客户端 → FIN_WAIT_1)
    S->>C: ② ACK=1, ack=u+1<br/>(服务端 → CLOSE_WAIT，客户端 → FIN_WAIT_2)
    Note over S: 服务端可能还有数据要发送...
    S->>C: ③ FIN=1, seq=w<br/>(服务端 → LAST_ACK)
    C->>S: ④ ACK=1, ack=w+1<br/>(客户端 → TIME_WAIT，等2MSL后CLOSED)
    Note over S: 服务端收到ACK → CLOSED
    end
```

### 高频面试题速记

| 问题 | 答案 |
|------|------|
| 为什么要三次握手？ | 防止已失效的连接请求到达服务端，造成资源浪费（确认双方收发能力） |
| 为什么要四次挥手？ | TCP 是全双工，每个方向需要单独关闭（FIN + ACK） |
| 为什么 TIME_WAIT 等 2MSL？ | ① 确保最后一个 ACK 到达对方 ② 让旧连接的报文在网络中消失 |
| accept() 在哪个阶段？ | 三次握手完成之后，从全连接队列取出连接 |
| SYN Flood 攻击原理？ | 大量发 SYN 不回 ACK，撑满半连接队列 |

```mermaid
mindmap

    序列号与确认号
      每个字节都有序号
      累积确认机制
    超时重传
      RTT动态计算
      指数退避
    滑动窗口
      发送窗口
      接收窗口
      窗口大小通告
    流量控制
      接收方通过窗口大小控制发送速率
      窗口为0时探测机制
    拥塞控制
      慢启动 Slow Start
      拥塞避免 Congestion Avoidance
      快重传 Fast Retransmit
      快恢复 Fast Recovery
    校验和
      检测数据完整性
```

### HTTPS（TLS 1.2）握手过程

```mermaid
sequenceDiagram
    participant C as 客户端
    participant S as 服务端

    C->>S: ① ClientHello<br/>(支持的TLS版本、加密套件、随机数Client Random)
    S->>C: ② ServerHello<br/>(选定的加密套件、随机数Server Random)
    S->>C: ③ 服务端证书（含公钥）
    S->>C: ④ ServerHelloDone

    Note over C: 验证证书合法性（CA链）
    C->>S: ⑤ Client Key Exchange<br/>(用服务端公钥加密 Pre-Master Secret)

    Note over C,S: 双方用 Client Random + Server Random + Pre-Master Secret<br/>生成对称密钥 Session Key

    C->>S: ⑥ ChangeCipherSpec + Finished
    S->>C: ⑦ ChangeCipherSpec + Finished

    Note over C,S: 🔐 后续通信使用 Session Key 对称加密
```

## 九、常见网络攻击与防御

```mermaid
mindmap
  root((网络安全))
    SYN Flood
      原理：大量半连接撑满队列
      防御：SYN Cookie / 增大队列
    XSS 跨站脚本
      原理：注入恶意脚本
      防御：输入过滤 / CSP / HttpOnly
    CSRF 跨站请求伪造
      原理：利用用户已登录的身份
      防御：Token / SameSite Cookie / Referer检查
    SQL注入
      原理：拼接恶意SQL
      防御：参数化查询 / ORM
    中间人攻击 MITM
      原理：拦截篡改通信
      防御：HTTPS / 证书校验
    DDoS
      原理：海量流量压垮服务
      防御：CDN / 流量清洗 / 限流
```

## 十、高频对比速查表

| 对比项 | 区别 |
|--------|------|
| **TCP vs UDP** | 可靠连接 vs 无连接不可靠；字节流 vs 报文 |
| **HTTP vs HTTPS** | 明文 vs 加密（TLS）；80端口 vs 443端口 |
| **GET vs POST** | 参数在URL vs Body；幂等 vs 非幂等；可缓存 vs 不可缓存 |
| **Cookie vs Session** | 客户端存储 vs 服务端存储 |
| **正向代理 vs 反向代理** | 代理客户端（翻墙）vs 代理服务端（Nginx负载均衡） |
| **长连接 vs 短连接** | 一次TCP多次请求 vs 每次请求新TCP |
| **交换机 vs 路由器** | 数据链路层/MAC vs 网络层/IP |
| **同步 vs 异步** | 调用者等待结果 vs 回调通知 |
| **阻塞 vs 非阻塞** | 线程挂起等待 vs 立即返回 |
| **select/poll/epoll** | 遍历O(n)/遍历O(n)/回调O(1)；fd有限/无限/无限 |
