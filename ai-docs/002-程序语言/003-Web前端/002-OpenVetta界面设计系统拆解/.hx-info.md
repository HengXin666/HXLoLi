# OpenVetta 界面设计语言知识点

## OpenVetta 的界面规范先写成一份可机械自查的硬性文档, 再把"单一事实源"声明为 styles.css 里的 CSS 变量

- 规范文件是 `apps/desktop/DESIGN.md`, 全文 259 行, 开头声明它是改动 renderer 下任何 UI 的必读硬性规范, 与本文件冲突的现存代码被定义为待清理的债, 不许当范例复制.
- 规范的单一事实源被指定为 `apps/desktop/src/renderer/styles.css` 里的 CSS 变量与 `@theme inline` 块.
- 文档结构是分节规范加一张 9 条的提交前勾选表 (§9 Lint checklist), 勾选项全部可机械检查. 九条原文依次是: 没有 hex / `rgb(` / 默认 Tailwind 调色盘 (除 §1.3 白名单的 emerald/amber); 没有 `shadow-[...]` 自定义任意值且卡片 hover 无 shadow 且按钮无发光阴影; 按钮一律用 `<Button>` + variant; 所有线条 1px (没有 `border-2/4`、`ring-2`、`outline-2`、`border-[Npx]`); 没有 `rounded-3xl` / `rounded-[Npx]`; 没有 `transition-all`; hover `whileHover` 不超过 §5.1 表格; 顶栏拖拽区域单独 `<div className="drag-region h-12 shrink-0" />`; 没有手写 scrollbar 样式.
- 依据: `apps/desktop/DESIGN.md` 开头引言与 §9 lint checklist 全文.

## 颜色只能来自语义 token, hex、rgb()、hsl() 与 Tailwind 默认调色盘一律禁止

- 合法来源是 `@theme inline` 暴露的 token 工具类及其 alpha 变体, 页面底用 `bg-background`, 卡片面 `bg-card`, 浮层面 `bg-popover`, 主色 `bg-primary`, 次要面 `bg-secondary`/`bg-muted`/`bg-accent`, 次要文字 `text-muted-foreground`, 边与输入与环 `border-border`/`bg-input`/`ring-ring`, 危险 `bg-destructive`.
- 被点名的默认调色盘包括 slate、zinc、gray、sky、violet、pink、orange.
- 需要透明混合时写 `color-mix(in srgb, var(--primary) 30%, transparent)`, 不写内联 style 色值.
- 依据: `apps/desktop/DESIGN.md` §1.1 表格与 §1.2 禁止项.

## 颜色透明度只允许十个固定档位, 不允许随手取值

- 允许的 alpha 后缀是 `/5 /10 /15 /20 /25 /30 /40 /50 /60 /70 /80`.
- 固定档位的意义在于任意两个界面片段的透明层次能对齐, 例如 `bg-primary/10` 在导航选中块、标签、卡片强调态里是同一个值.
- 依据: `apps/desktop/DESIGN.md` §1.1 末段.

## 只放行三种 Tailwind 原色充当语义色, 业务标签色必须降级为 token 叠色

- 成功与运行中: `bg-emerald-500/15` 配 `text-emerald-400`.
- 警告与可更新: `bg-amber-500/15` 配 `text-amber-400`.
- 错误必须用 `destructive` token, 禁止 `red-*`.
- 自定义、实验、Beta 这类业务标签一律写成 `bg-primary/10 text-primary` 或 `bg-accent/60 text-muted-foreground`, 不引入 violet 或 sky 或 pink.
- 依据: `apps/desktop/DESIGN.md` §1.3 白名单表.

## 暗色是默认, 亮色是一套独立取值, 靠 data-mode 属性切换

- `:root` 本身就是暗色定义, 亮色写在 `[data-mode="light"]` 块内.
- 亮色并非暗色的机械反相: 主色从 `rgb(99,102,241)` 压到 `rgb(79,70,229)` 以保住白底对比度, 终端 ANSI 十六色整组重调.
- 切换主题期间的过渡由根元素上的 `theme-transitioning` 类承担, 只过渡 background-color、color、border-color、fill、stroke、box-shadow 六个属性, 不碰 transform 与 opacity.
- 依据: `apps/desktop/src/renderer/styles.css` 的 `:root`、`[data-mode="light"]`、`[data-theme].theme-transitioning` 三个块.

## 多分段图表色做成等亮度等饱和, 只靠色相区分

- 上下文构成的五段色写作 `oklch(0.72 0.12 268 / 215 / 165 / 95 / 25)`, 亮度和彩度五个数值全部相同, 只有色相在变.
- 代码注释写明的理由是避免相邻分段因明度差被读成一高一低, 那会让读者把并列关系误读成大小关系.
- 依据: `apps/desktop/src/renderer/styles.css` 的 `--context-segment-1..5` 及其注释.

## 所有线条统一 1px, 加重分隔靠更深的 token 颜色而不靠加粗

- border、divider、ring、outline 全部 1px, 禁止 `border-2`、`border-4`、`ring-2`、`outline-2` 及以上.
- 禁止 `border-[Npx]` 这类任意值.
- 选中态与 focus 态同样走 `ring-1 ring-inset`.
- 需要更强的分隔时把颜色从 `border-border/40` 提到 `border-border`, 或者叠一层 `bg-*`.
- 依据: `apps/desktop/DESIGN.md` §2.0.

## 圆角按元素角色分五档, 并且由单个 --radius 变量派生

- 卡片、面板、grid 卡用 `rounded-xl`; 列表项、输入框、常规按钮用 `rounded-lg` 或 `rounded-md`; 高度不超过 9 的小 chip 用 `rounded-lg`; pill、标签、segmented control、圆形图标按钮用 `rounded-full`; Hero 或超大装饰容器用 `rounded-2xl` 且只允许一处作为视觉锚点.
- 禁止 `rounded-3xl` 及以上与任意 `rounded-[Npx]`.
- `--radius` 取 `0.5rem`, 派生 `--radius-sm` 到 `--radius-xl` 四档, 因此改一个变量就能整站改圆角手感.
- 依据: `apps/desktop/DESIGN.md` §3 表格; `apps/desktop/src/renderer/styles.css` 的 `@theme inline` 块.

## 卡片默认零阴影, 层级靠 1px 边框加半透明底色叠出来

- 卡片基线类串是 `rounded-xl border border-border/50 bg-card/40 backdrop-blur-sm transition-colors duration-200 hover:border-primary/40 hover:bg-card/60`.
- hover 只更换边框颜色和背景透明度, 不加阴影、不放大、不平移超过 2px.
- 依据: `apps/desktop/DESIGN.md` §2.1.

## 阴影是白名单制, 并且明确否决主色发光阴影

- 普通卡片、列表项、grid 卡一律无阴影.
- Popover、Dropdown、Dialog 允许 `shadow-md` 或 `shadow-lg`; 拖拽中的元素用 `shadow-lg`; Toast 与浮动条用 `shadow-md`.
- 禁止卡片 hover 加阴影, 禁止 `shadow-[...]` 任意值, 禁止带主色的发光阴影, 例如 `shadow-[0_4px_16px_-6px_var(--primary)]`.
- 依据: `apps/desktop/DESIGN.md` §2.2 表格与禁止项.

## 强调态用 ring 而不是 shadow, 并且 ring 常驻不发光

- 被选中的列表项、活跃 session、当前项目写成 `ring-1 ring-inset ring-primary/30` 加 `bg-primary/10` 加 `border-primary/40`.
- 依据: `apps/desktop/DESIGN.md` §2.3.

## 间距与网格间距按三档给, 网格列数用 auto-fill 自适应而不写死

- 紧凑列表项高约 40 用 `px-3 py-2.5`; 标准卡片用 `px-3.5 pt-3 pb-3`; 宽松卡片与设置面板用 `p-4`; 页面外层用 `px-8` 加 `pb-8`; Popover 内菜单项用 `px-2.5 py-1.5`.
- 网格间距三档: 紧凑卡片 `gap-2.5`, 标准卡片 `gap-3`, 大块统计 `gap-4` 到 `gap-5`.
- 自适应列写成 `grid-cols-[repeat(auto-fill,minmax(240px,1fr))]`(小卡) 或 `minmax(320px,1fr)`(行式列表), 禁止写死 `grid-cols-3`.
- 依据: `apps/desktop/DESIGN.md` §4.1 §4.2.

## 字号只有七档, 字族三档全部走 token

- 允许的字号是 `text-[10px]` `text-[11px]` `text-[12px]` `text-[13px]` `text-[14px]` `text-[15px]` 与 `text-[20px]` 以上用于统计数字.
- 字族由 `--font-sans`(系统 sans 栈)、`--font-serif`、`--font-mono` 三个变量提供.
- 依据: `apps/desktop/DESIGN.md` §4.3; `apps/desktop/src/renderer/styles.css` 的 `:root` 块.

## hover 动效有明确上限, 卡片与按钮不允许同时改动多个视觉属性

- 规范 §5.1 的总则原文是: UI 是工具, 不是 showroom. hover 只反馈, 不表演.
- 卡片 hover 的上限是 `whileHover={{ y: -2 }}`, 不允许叠加 scale、rotate、shadow.
- 按钮 hover 上限是 `scale: 1.04`, tap 下限是 `scale: 0.94`.
- 进入动画表达式为 `opacity 0→1` 加 `y 8→0`, 或加 `scale 0.97→1`, duration 不超过 0.5s.
- stagger 取 `0.04` 到 `0.06`, `delayChildren` 不超过 `0.15`.
- 依据: `apps/desktop/DESIGN.md` §5.1 表格.

## spring 参数写成固定数字而不是随手调

- 入场用 `{ type: "spring", stiffness: 280~320, damping: 26 }`.
- 按钮交互用 `{ stiffness: 380, damping: 22 }`.
- 依据: `apps/desktop/DESIGN.md` §5.2.

## 持续旋转、多属性联动 hover、超过 0.6s 的入场与 transition-all 四项被禁止

- 装饰性持续旋转或弹跳被禁止, loading spinner 除外.
- `whileHover` 同时改 y、scale、阴影被禁止.
- 入场动画长于 0.6s 被禁止.
- 写 `transition-all` 被禁止, 要用 `transition-colors` 或具体属性名.
- 依据: `apps/desktop/DESIGN.md` §5.3.

## 进行中指示动画由宿主统一挂载, 组件侧只写静止态

- 组件 CSS 里只允许写静止态, 不许写 `animation` 或 `@keyframes infinite`.
- 元素带登记过的类名即可获得动画, 现有类名是 `.processing-shimmer`、`.tool-call-shimmer-text`、`.vetta-live-dot`、`.todo-label-sheen`、`.todo-marker-spin`、`.activity-dot-halo`、`.activity-dot-core`、`.send-button-ripple-1`、`.send-button-ripple-2`.
- 静止态必须是相位 0 的外观, 例如光晕这类没有动画就该看不见的元素写成 `opacity: 0`.
- 依据: `apps/desktop/DESIGN.md` §5.4; `packages/theme-ui/src/styles.css` 顶部注释.

## 毛玻璃窗口下动画的帧成本是被实测过的, 因此呼吸动画改用 steps(16) 加时间线锁相

- 仓库注释给出的实测数据 (Chromium 132): opacity 与 transform 关键帧配 `steps(16)` 每秒画 12 帧且主线程接近零开销; 平滑曲线每秒 70 帧; 用注册自定义属性做时钟虽然帧数少, 但 Blink 每帧在主线程重算样式, 挂在 `:root` 上时每 300ms 耗 300ms/s.
- 实现方式是用 Web Animations API 为每个元素建 `steps(16, end)` 动画, 周期 `1600ms`, 迭代无限.
- 关键手法是把 `animation.startTime` 锁到文档时间线原点, 即 `startTime = 0 - offset * PERIOD_MS`, 这样不管元素何时挂载, 全页指示器都停在同一相位上换帧.
- 第二圈波纹用 `offset: 0.5` 错开半个周期.
- 规范 §5.4 的原文开头是: macOS 主窗口带毛玻璃, 页面每出一帧系统都要整窗重新合成; 一个 4px 的脉冲点用平滑关键帧逐帧插值, 就足以让流式全程 GPU 不闲.
- 该段对自定义属性时钟方案的收尾原话是: **不要再走这条路**.
- `300ms/s` 那个数字带着限定条件: 只有把时钟挂在 `:root` 上时才是这个量级.
- 依据: `apps/desktop/DESIGN.md` §5.4 原文; `apps/desktop/src/renderer/shared/lib/live-animations.ts` 顶部注释、`PERIOD_MS`、`STEPS` 与 `REGISTRY` 数组.

## 流式文字用亮度分级代替逐元素淡入, 使出帧数与内容更新节奏一致

- 最新短语写 `opacity: 0.55`, 次新短语写 `opacity: 0.8`, 更早的保持全亮.
- 亮度只在下一次放出短语时随框架重渲染改变, 不产生动画帧.
- 只动 opacity 以保持 inline 排版, 不使用 inline-block 或 transform, 避免换行位置变化与上下跳动; 也不加 `will-change`, 避免长回复里数百个片段被永久提升成合成层.
- `prefers-reduced-motion: reduce` 下三段亮度统一回到 1.
- 依据: `apps/desktop/src/renderer/styles.css` 的 `.markdown-streaming-tail` 一节及其注释.

## Dialog 出入场时长与缓动是写死的, 且出场态与静止态保持一致以免跳动

- 遮罩入场 200ms ease-out, 出场 150ms ease-in.
- 内容入场 200ms `cubic-bezier(0.22, 1, 0.36, 1)`, 从 `scale(0.96)` 到 `scale(1)`; 出场 150ms, 回到 `scale(0.96)`.
- 动画的终态保留 `translate(-50%, -50%)` 与居中类一致, 动画结束时不发生位置跳动.
- `prefers-reduced-motion: reduce` 下四条动画全部关闭.
- 依据: `apps/desktop/src/renderer/styles.css` 的 `vetta-dialog-*` 关键帧与相邻的 `@media (prefers-reduced-motion: reduce)` 块.

## 图标只用单一 collection 并配五档尺寸

- 新增图标优先 solar 线性风格, 写作 `icon-[solar--*-linear]`, 其次 mdi; 禁止引入 lucide、tabler 等其它 collection.
- 常用对照: 菜单 `menu-dots`, 关闭 `close-circle`, 删除 `trash-bin-trash`, 编辑 `pen-2`, 文件夹 `folder` 与 `folder-open`, 设置 `settings`, 铃铛 `bell`, 会话 `chat-round-line`.
- 尺寸五档: 行内状态点 `h-2.5 w-2.5`, chip 与 tag 内 `h-3 w-3`, 按钮内与菜单前缀 `h-3.5 w-3.5`, 卡片左侧图标块 `h-4 w-4`, Hero 与空状态 `h-8 w-8` 到 `h-10 w-10`.
- 图标颜色一律走 token, 禁止主色之外的原色.
- 依据: `apps/desktop/DESIGN.md` §6.1 §6.2.

## 图标按需生成, 插件自带样式可把图标规则与内联 SVG 一起打进自己的 CSS

- 宿主通过 `@plugin "@iconify/tailwind4"` 生成图标工具类, 并且只生成源码里扫得到的字面量.
- 插件在自己的 CSS 里写同一个 `@plugin`, 图标规则连同内联 SVG 进入插件的 `dist/style.css`, 宿主激活插件时加载, 类名自然存在.
- 宿主里的 `@source inline("icon-[...]")` 清单只覆盖尚未迁移的仓库内旧插件, 迁移一个就删一行.
- 依据: `apps/desktop/src/renderer/styles.css` 顶部 `@plugin` 与 `@source inline` 注释段.

## 滚动条做成 macOS 式 overlay, 默认透明且仅在容器被 hover 或获得焦点时显形

- 全局写 `scrollbar-width: thin` 与透明轨道, 滑块常态透明.
- 只在 `*:hover` 或 `*:focus-within` 时把滑块画成 `color-mix(in srgb, var(--muted-foreground) 35%, transparent)`, 悬停滑块本身时提到 60%.
- 宽高始终保持 8px 占位, 因此显隐不引起布局跳动.
- 规范禁止组件里手写 `::-webkit-scrollbar` 或 `scrollbar-width`, 否则会撕裂全局风格.
- 依据: `apps/desktop/src/renderer/styles.css` 的 "macOS-style overlay scrollbars" 一节; `apps/desktop/DESIGN.md` §7.3.

## 窗口拖拽区用独立的空白元素占位, 交互元素必须反向声明可点击

- 拖拽区写 `.drag-region { -webkit-app-region: drag }`, 内部交互元素写 `.no-drag`.
- 新页面顶部先留 `<div className="drag-region h-12 shrink-0" />` 作为可拖拽空白, 再写页面 header, 不把 header 自身设为拖拽区.
- 依据: `apps/desktop/src/renderer/styles.css` 的 `.drag-region` 与 `.no-drag`; `apps/desktop/DESIGN.md` §7.1 §7.2.

## 选中高亮、焦点与光标被一次性 token 化, 组件不得局部覆盖

- `::selection` 全局写成 `color-mix(in srgb, var(--primary) 42%, transparent)` 配 `var(--foreground)`.
- `:focus-visible` 全局设 `outline: none`, 交互控件改用 1px 边框变色表达焦点, 例如输入框聚焦时从 `border-border/60` 变为 `border-ring/60`.
- 光标由一组变量提供, 默认解析到系统原生光标, 只有根元素带 `custom-cursor` 类时才覆盖为图片素材; 连 `caret-color` 都绑定到主色 token.
- 依据: `apps/desktop/src/renderer/styles.css` 的 "Selection highlight"、"Focus"、光标变量三节.

## macOS 原生毛玻璃侧边栏需要在子树内把强调色换成半透明叠加色

- 做法是窗口开启 vibrancy, 应用整帧与侧边栏都不上底色, 由主内容区用 `::before` 覆盖负边距 8px 补回不透明背景, 于是只有侧边栏那一条透出桌面.
- 侧边栏在毛玻璃上再铺一层半透明 `--background`, 浓度由 `--sidebar-vibrancy-tint` 控制, 亮色模式单独调淡到 35%.
- 必须把侧边栏子树内的 `--accent` 替换为 `color-mix(in srgb, var(--foreground) 10%, transparent)`, 原因是主题里的 `--accent` 是不透明实色, 背后桌面的明暗会让高亮块与底色的明暗关系反转, 看起来像选中背景消失.
- 明暗切换期间先把这一层改成不透明并关掉过渡, 因为原生 vibrancy 由主进程翻转, 不进 View Transition 快照, 会比页面动画早一步瞬变.
- 这条在本次产物里被收进独立的 `src/desktop/` 分组, 选择器一律带 `:root[data-platform="mac"]` 前缀: 纯 Web 环境不打 `data-platform` 标记, 这组规则就不命中, 因此可以直接引入而不会污染非桌面环境.
- 依据: `apps/desktop/src/renderer/styles.css` 的 `[data-platform="mac"][data-sidebar-style="classic"]` 系列规则及其注释; 本次复现产物 `src/desktop/desktop.css`.

## 列表树的连接线是纯 CSS 伪元素画的, 最后一项用 L 形圆角收口

- 每个 `li` 相对定位并左内边距 18px.
- 非末项的 `::before` 画一条通高 1px 竖轨, `::after` 在首行高度处画一条 12px 横枝.
- 末项的 `::before` 改为向左下弯的 L 形, 高 0.95rem 宽 12px 并带左下圆角 7px, `::after` 取消.
- `li` 内段落上下外边距清零, 使横枝对准第一行文字而不是段落框.
- 依据: `apps/desktop/src/renderer/styles.css` 的 `.md-bullet-list` 一节.

## 表格数值列强制等宽数字, 表头列间的竖分隔只有一字高

- 表格容器加 `font-variant-numeric: tabular-nums`, 使上下行的小数点对齐.
- 表头相邻列的竖线做成 1em 高、垂直居中的伪元素, 而不是通高的 border, 避免把表头切成一排格子.
- 依据: `apps/desktop/src/renderer/styles.css` 的 "Markdown 表格" 一节.

## 按钮只有唯一来源, 语义 variant 与自拼样式之间没有中间地带

- 必须使用共享 `<Button>` 组件加 variant, 禁止手写 `<button>` 或 `<motion.button>` 自拼 `rounded-full bg-gradient-to-* px-4 py-2` 这类样式.
- 语义映射: 主操作用 `primary`, 次要用 `outline` 或 `secondary` 或 `ghost`, 危险操作用 `destructive`.
- 禁止给按钮加发光或自定义阴影, 主操作直接用 `variant="primary"`.
- 位置与间距的微调只允许通过 `className` 传入.
- 依据: `apps/desktop/DESIGN.md` §8.

## 基础件的 variant 维度由 cva 定义, 并且用数据属性驱动内边距

- `packages/ui/src` 收录 `button` `calendar` `date-picker` `dialog` `drawer` `dropdown-menu` `input` `popover` `select` `slider` `spin` `switch` 与 `utils`, 依赖 `radix-ui` 单包、`class-variance-authority`、`tailwind-merge`、`clsx` 与 `vaul`.
- Button 的尺寸维度有 `default` `xs` `sm` `lg` `icon` `icon-xs` `icon-sm` `icon-lg` 八档, 基准类串以 `rounded-lg border border-transparent` 开头.
- 内边距由子元素决定, 例如 `has-data-[icon=inline-end]:pr-2`, 因此传入图标时不需要手调 padding.
- 类名合并由 `cn()` 完成, 实现是 `twMerge(clsx(...))`.
- 依据: `packages/ui/src/index.ts`、`packages/ui/src/button.tsx`、`packages/ui/src/utils.ts`.

## Dialog 宽度用单条 max-width 表达, 避免断点前缀在合并时反过来盖住使用方

## 主题能力分三档, 且刻意不合并进同一个 API

- Appearance config: 不写组件, 只配置 surface 装饰, 对应只换图片边框、加背景纹理这类需求.
- Component override: 不重写父级, 只替换默认 UI 中的某个局部组件, 对应换按钮、列表项、消息气泡.
- Region override: 接管完整区域, 可以自由新增组件与重排布局, 同时复用 Theme SDK.
- 依据: `docs/theme/architecture.md` 的"目标"与"三层模型"两节.

## 主题与应用之间隔着一层抽象模型, 主题不许触碰数据层

- 三层是 App Data Center(状态、路由、进程通信、业务 hooks) 到 UI Abstract Layer(model hooks、view model、actions、region 契约) 到 UI Implementation Layer(默认 UI、共享 UI、装饰组件、远程主题组件).
- 主题不得直接访问内部状态 atom、进程通信对象、路由原始细节、领域私有 hook 以及文件系统与网络等底层能力.
- 语义文案、aria 与 title、业务状态与动作属于 model 层; 图标、图片、CSS 类、动画与装饰素材属于 UI 实现层.
- 依据: `docs/theme/architecture.md` 的"三层模型"一节.

## 主题自有状态走独立存储通道, 并按主题 id 隔离

- 接口是 `useThemeStorage` 与 `useThemeStorageValue`, 来自 theme-sdk 的 storage 子路径.
- 宿主按当前主题的 `meta.id` 隔离, 主题无法指定其它主题 id.
- 落盘位置是 `~/.vetta/desktop-app/themes/<themeId>/data.json`.
- 依据: `docs/theme/architecture.md` 数据层一节; `packages/theme-sdk/src/storage/`.

## 组件要进入公开 UI 库需要同时满足八项标准

- 行为边界清楚, 只负责渲染与局部交互, 不拥有跨领域流程.
- props 稳定, 主题能通过 props 拿到渲染所需的数据与动作.
- 不依赖内部 store, 不要求主题 import 状态 atom、路由、进程通信或领域私有 hook.
- 样式可组合, 支持 `className`, 复合组件支持 `classNames`.
- 需要充当 trigger、button、row、focus target 的组件必须 `forwardRef`.
- 用户可见文案走 i18n, 不在组件中硬编码中文.
- 需要主题装饰的区域提供 root、decoration、content 三层.
- 主题未提供 override 时默认行为不变.
- 依据: `docs/theme/component-guidelines.md` 的"组件开放标准"一节.

## 主题组件的 props 只表达 UI 契约, 内部对象与 UI 专属字段都不进 props

- 推荐写法是继承合适的 DOM props 以保留 onClick、disabled、title 与 aria 能力, 动作暴露为语义函数如 `onOpenSession`, 数据暴露为 view model 类型如 `SidebarNavItem`.
- 避免写法是暴露 atom setter、router navigate、进程通信对象、内部记录类型, 以及把图标 class 或布局 class 或动画参数塞进数据对象.
- 可选 props 必须有清晰的默认行为, 异步 action 返回 `Promise<void>`.
- 依据: `docs/theme/component-guidelines.md` 的"Props Contract"一节.

## 主题在 manifest 里逐个 slot 声明能力, 不是整个界面全给

- 仙侠主题的 `theme.json` 声明 `runtime: module-federation`、`entry: dist/mf-manifest.json`.

## 指示器动画由 MutationObserver 在节点进出时挂载与卸载

- 调度器对根节点开一个 `MutationObserver`, 监听 `childList` 与 `subtree`; 新增节点走 `attach`, 移除节点走 `detach` 取消动画.

## 减少动态偏好由调度器读一次媒体查询整体跳过, 不逐条写分支

- `prefersReducedMotion()` 用 `matchMedia("(prefers-reduced-motion: reduce)")` 判断; 命中时 `installLiveAnimations` 直接返回空卸载函数, 一个动画都不创建.
- 这就是"CSS 只写静止态"的回报: 没有动画时元素停在相位 0, 而那正是它正常该有的外观.
- 依据: `apps/desktop/src/renderer/shared/lib/live-animations.ts` 的 `prefersReducedMotion` 与 `installLiveAnimations` 开头 (第 75 至 76 行、第 121 行).

## 设置页的两级导航把"展开"做成选中态的表现, 而不是独立状态

## 主题预览卡不是截图, 是用真实主题色实时画出来的

- 每张卡先用 `aspect-[16/9]` 定比例, 底色直接取该主题的 `palette.background`.
- 背景氛围由五个绝对定位的圆组成, 统一被父层 `filter: blur(28px) saturate(115%)` 糊开; 每个圆取调色盘里不同的色 (`primary` / `accent` / `ring` / `chart1` / `chart2`), 尺寸 55% 到 75% 不等, 各自带一个较大的旋转角度错开.
- 中间再叠一个用同一套色画出来的**迷你窗口模型** (标题栏三个点 + 四行不同宽度的文字条 + 两个按钮块), 模拟真实界面结构.
- 这样加一个主题就自动多一张预览, 不需要准备图片; 且预览永远不会与真实配色不一致.
- 依据: `AppearanceSettingsView.tsx` 的 `BLOB_LAYOUT` 常量与 `ThemeCard` 实现.

## 换主题用 View Transition 从点击位置做圆形揭示

- 点击时把 `event.clientX/clientY` 一路传下去, 最终算出一个足以覆盖全屏的半径: `Math.hypot(max(x, 宽 - x), max(y, 高 - y))`.
- 揭示动画直接在 View Transition 的伪元素上做: `clipPath` 从 `circle(0px at x y)` 到 `circle(半径 at x y)`.
- 动画挂在 `pseudoElement: "::view-transition-new(root)"` 上, 而不是把坐标写成会继承到整棵 DOM 的根节点 CSS 变量.
- 用 `transition.ready` (在伪元素树建好、首次绘制之前兑现) 再启动动画, 因此不会闪出未经裁剪的新页面.
- 不支持该 API 或用户开了"减少动态"时, 回退成单纯的颜色过渡.
- 依据: `apps/desktop/src/renderer/shared/theme/apply.ts` 的 `withThemeTransition` 与 `animateThemeReveal`.

## 边界

- 以上结论的成立前提是"用 Tailwind v4 且允许自定义 CSS 变量"这一技术栈. 换成 Tailwind v3 的 config 式主题, `@theme inline` 桥接与 `/N` alpha 档位的写法都需要改写.
- 动效一节的性能数字 (steps(16) 每秒 12 帧、平滑曲线每秒 70 帧、自定义属性时钟 300ms/s) 是仓库作者在 Chromium 132 与 macOS 毛玻璃窗口下的实测值, 本次未复现, 换平台与换浏览器后这些数字不保证成立.
- 毛玻璃侧边栏一节依赖 Electron 的 `vibrancy` 窗口选项, 纯网页环境无法还原, 只能退化为半透明叠加.
- `--sidebar-vibrancy-tint` 在暗色取 60%、亮色取 35% 这两个数值来自注释说明, 未在本机实测; 这两个值属于需要按壁纸明暗微调的观感参数.
- 未采集侧边栏、聊天页等具体组件的内部布局, 因此"某个面板内部怎么排"不在本次结论范围内.
- 已知反例: 仓库自己的 §10 记录了存量违规文件, 复现时不应以它们为范例; 该节当前内容为"暂无", 意味着规范执行是持续的清理过程而不是一次性达标.
- `[不确定]` 图标尺寸五档与字号七档这类"允许清单"的具体数值, 是规范作者的取舍; 本仓库未记录这些取值是如何收敛来的, 因此无法判断换一个产品定位是否仍合适.
